# Next plan: finish the FD/eventfd slice, then WireGuard, 2026-09-29

Status: **agreed direction** [USER 2026-09-29]. It extends the
[way-forward plan](2026-09-29-way-forward.md). That plan's principles
(section 3), assurance model (section 4) and signoff rules still govern:
- the mirror is behavioral only, with no theorem proving;
- the mirror keeps data and control-flow correspondence with the C;
- every update to `main` needs the user's signoff on the concrete diff.

## 1. Where the project stands

The FD/eventfd slice of Linux 6.12.110 (x86-64) is essentially complete, as
the way-forward plan defines complete.

**Mirror.**
- C-shaped state: finite and comparable, with explicit refcounts, `f_op` and
  `private_data`.
- One Lean function per C function.
- 161 C decision points recorded in C order; 58 of them are declared value
  comparisons that report their operands.
- Named cut points for unmodeled mechanisms; an explicit environment oracle;
  structured stops that separate domain exits from mirror defects.

**Check.** One command, `python3 -m evaluator.check`, runs about 1,000 traces
on the pinned kernel in QEMU and on the mirror. It requires agreement on:
- observable behavior;
- KCOV control flow, two-sided, including decisions the mirror did not report;
- decision order within each C function;
- the operands of declared comparisons, from `KCOV_TRACE_CMP`.

Five kinds of planted bug are rejected, four of them behavior-preserving.
Residual gaps are listed in [correspondence/README.md](../correspondence/README.md).

## 2. Finish the slice (done on `task/phase4-domain`, awaiting signoff)

1. **Phase 4 part 1:** domain widening and mirror-filtered generation. Done on
   `task/phase4-domain`, awaiting signoff.
2. **`F_SETFL`.** `do_fcntl` → `setfl` (fs/fcntl.c) changes `f_flags` on a
   live file. It interacts with blocking eventfds: a nonblocking eventfd can
   become blocking and back. It adds the `setfl` decisions, and `f_lock` as a
   cut point.
3. **fd-table expansion beyond 64 slots.** `expand_files` → `expand_fdtable` →
   `alloc_fdtable`/`copy_fdtable`, with RCU replacement of `files->fdt`, the
   `resize_in_progress` protocol, and the retry in `alloc_fd`.
   - This needs `RLIMIT_NOFILE` above 64. The fixture's limit becomes an
     optional trace parameter (default 32), set by the guest before the first
     operation.
   - It exercises the full-word bitmap paths (`full_fds_bits`), which are
     unreachable today.
4. **Report.** Close the slice with a short report: what the mirror covers,
   the evidence, the residual gaps, and the per-function effort. Effort
   matters because it predicts the cost of the next component.

Deferred, not planned for this slice:
- allocation-failure injection;
- user-memory addresses and faults;
- operations on fixture files;
- concurrency.

## 4. WireGuard (after the finish-up)

**Why.** WireGuard (`drivers/net/wireguard`, about 5,200 lines) is a
self-contained, security-relevant subsystem. Its cryptokey routing and replay
protection give crisp invariants for later proofs. It tests the method on a
second component several times the size of the current slice.

**Constraints found on 2026-09-29.**
- The pinned kernel is built with `CONFIG_NET` off.
- WireGuard's data path runs in workqueues and NAPI/softirq, which KCOV's
  per-task mode does not see.
- It has about 54 locking, RCU and queueing sites.
- Handshakes use randomness and timers.
- Crypto primitives are partly SIMD assembly.

**User decisions** [USER 2026-09-29]:
- **U1.** A new kernel configuration with networking is approved: `NET`,
  `INET`, IPv6, `NET_NS`, `VETH`, `WIREGUARD` and their crypto libraries. It
  gets its own identity and output directory, and evidence is re-established
  on it. The current kernel stays the accepted oracle for the FD/eventfd slice
  until the new one is validated.
- **U2.** An instrumentation-only test kernel build for stage B is approved.
  It adds KCOV remote-coverage handles to WireGuard's workqueue and NAPI
  paths. It is separately versioned; the patch changes only instrumentation,
  never behavior, and is recorded with its hash.

**Stages.** Each stage ends with a branch, evidence, and a request for signoff.

| Stage | Scope | Main risks |
|---|---|---|
| A | New networking kernel. Guest network namespace with a veth pair. Trace operations for netlink configuration (device, peers, allowed IPs) and for queries. Mirror of `netlink.c`'s set/get paths, `peer.c`, `peerlookup.c` and `allowedips.c`. Routing is observed through packets on the veth pair. | Harness extension (netlink, sockets); the new kernel identity |
| B | Remote-coverage test kernel (U2). Packet injection. Mirror of message parsing and validation, the replay counter, the rate limiter and cookie validation in `receive.c`, `cookie.c` and `ratelimiter.c`. | Remote KCOV plumbing; serializing the receive path in the harness |
| C | Noise handshake state machine (`noise.c`), with randomness and time as oracle inputs. Checks become structural where values are unobservable. | Randomness; timers |
| D | Full send/receive pipelines with concurrency. | Needs a concurrency design for the mirror and for the logic; out of scope until A–C and section 3 are done |

**Stage A design** [AGENT 2026-09-30]:
- **Kernel.** `scripts/build-kernel` with `LEANUX_KERNEL_PROFILE=net` adds
  `NET`, `UNIX`, `INET`, `IPV6`, `NET_NS`, `NETDEVICES`, `VETH` and
  `WIREGUARD` to the same minimal base. It reports release `-leanux-kcov-net`
  and records `kernel/config-x86_64-net`. `WIREGUARD` selects the x86-64
  crypto implementations (`CRYPTO_CURVE25519_X86` and others), so Curve25519
  runs `curve25519_arch`/`curve25519_base_arch`; the mirror's RFC 7748
  reference computes the same function. [Corrected 2026-09-30 after review;
  the design first said the generic C implementations were used.]
- **Fixture.**
  - Each trace child calls `unshare(CLONE_NEWNET)` and creates `wg0` with
    rtnetlink, and the device is never brought up. Device creation
    (`wg_newlink`) is fixture, not trace.
  - With the device down, `set_port` only stores the port, and no UDP sockets,
    timers or handshakes run.
  - Everything stays in process context, so per-task KCOV applies.
- **Trace operations.**
  - `wg_set`: a structured `WG_CMD_SET_DEVICE`, covering the private key,
    listen port, fwmark, replace-peers flag, and peers with public key,
    preshared key, flags (remove, update-only, replace-allowed-ips), endpoint,
    keepalive and allowed IPs.
  - `wg_get`: a `WG_CMD_GET_DEVICE` dump.
- **Encoding and decoding in Python.** The Python harness encodes the
  attribute payload. The guest resolves the generic-netlink family ID, sends
  the request and returns raw dump payloads, and Python decodes them into a
  canonical device state. Dump message boundaries are coalesced, as the UAPI
  tells receivers to do; this is a stated abstraction.
- **Mirror scope.**
  - `netlink.c`: the set and get paths, with attribute-policy validation
    (`nla_parse`) as a cut point;
  - `peer.c`: create and remove, with timers, queues, NAPI and RCU freeing as
    cut points;
  - `peerlookup.c`: the public-key table, as a map, since its bucketing seed
    is random;
  - `allowedips.c`: the trie, in full, including each peer's list order.
- **Crypto.** Curve25519 public-key derivation and the static-static
  precomputation are realized by a reference implementation in Lean, behind a
  named contract.
- **Order of work.**
  1. The harness on Linux alone: fixture, set/get, decoded observations.
  2. The `allowedips` trie mirror.
  3. Peers and keys.
  4. The full set/get paths.
  5. Mutants and review.

**Cut points and principles** carried over from the FD/eventfd slice:
- Crypto (Curve25519, ChaCha20-Poly1305, BLAKE2s) is a named contract,
  realized by reference implementations or oracles, not mirrored.
- `sk_buff` handling is abstracted to packet contents and lengths, with the
  abstraction stated at each cut point.
- The generic networking stack outside `drivers/net/wireguard` is a contract,
  not mirrored.

**Stage A done** means all of the following:
- the check passes on the networking kernel for both the FD/eventfd corpus and
  a WireGuard configuration corpus;
- the `allowedips` mirror's decisions, order and operands agree with KCOV;
- a mutant corpus is rejected;
- the per-function effort is recorded.

**Stage B1 design** [AGENT 2026-09-30; revised after the Linux probes and the
structural review]:
- **Fixture.** In network traces, `lo` is up. Descriptors 4 and 5 are UDP
  listeners on 127.0.0.1 and ::1 at a fixed port, and descriptor 6 is a
  dual-stack UDP sender. Descriptor numbering is unchanged.
  - `wg_up` also adds an address and a default route on `wg0` for each family,
    outside the KCOV window, so the sender's datagrams reach `wg_xmit`.
  - An `AF_PACKET` sender was the first plan. The networking kernel has no
    `CONFIG_PACKET`, and a kernel change is outside U1, so the plan changed.
    The price is one unreachable arm (`wg_xmit.bad_protocol`).
- **Operations.**
  - `wg_up`: `IFF_UP` by `ioctl(SIOCSIFFLAGS)` on descriptor 6, which runs
    `wg_open`.
  - `wg_xmit`: a 4-byte UDP datagram to an IPv4 or IPv6 destination.
    Destinations the sender's IP layer handles before routing are invalid
    (`harness/wg.py`).
  - `wg_observe`: waits 0.4 s, then `recvfrom` on the IPv4 listener. It
    reports every datagram both listeners received and `wg0`'s transmit
    counters.
- **The handshake worker is a cut point**, with a contract. An initiation is
  sent iff all three hold: the device has an identity, the precomputed
  static-static is nonzero, and the peer has an endpoint. A sent initiation
  adds 148 to `tx_bytes`.
- **Races are outside the domain.**
  - While a peer's handshake work is queued and may have run, operations that
    read or change what the worker touches are `unsupported`. Work queued
    earlier in the same system call, before it slept, is known not to have
    run, because the kernel is `CONFIG_PREEMPT_NONE` on one CPU.
  - The device goes up once and never down.
  - Listen port 0 and the fixture's port are `unsupported`.
- **Time.** The guest fails a trace that runs longer than 4 s after `wg_up`,
  below `REKEY_TIMEOUT` (5 s). The guest blocks on `getrandom` before the
  batch, so that the worker's `wait_for_random_bytes()` never waits.
