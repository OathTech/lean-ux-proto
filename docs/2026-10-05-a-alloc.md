## 1. Target

Today the mirror has 23 `envOk` consultations (`grep -rn 'envOk \.'
Leanux/`) at 20 `EnvSite`s (`Leanux/Kernel/Defs.lean:209-219`), each
answered `true` by `harnessEnv`. Every allocation-failure arm in the mirror —
`wg_peer_create.no_mem`, `alloc_fdtable.kmalloc_failed`,
`encrypt_packet.cow_data_failed`, 17 more — is dead code: never taken by the
mirror, never confirmed against Linux, and no mutant of it can be rejected.
The comparator absorbs any Linux `ENOMEM` as an `environment_failure`
(`evaluator/protocol.py:101-116`), a declared fail-open spot.

A makes allocation outcomes **captured choices** like random draws and clock
reads (strategy section 3): recorded by a generic hook with the consumer's
call chain, consumed by the mirror in sequence order, and **steerable** to
failure at named sites through the existing per-handle schedule, within the
domain section 3 establishes. After A:
- every `envOk` site becomes a hidden choice site consumed from records,
  fail-noisy when a record is missing or unexpected (after the phased flip
  of section 6.6);
- the steerable failure arms are reachable by steered traces and confirmed
  by A1 (behaviour), A2 (the arm's KCOV spans) and the new records;
- the `environment_failure` absorption of `ENOMEM` is retired;
- pipes (P) add allocation sites by **declaration only**, which is the
  scalability claim of strategy section 10, step 7, tested on a second kind
  of choice.

## 3. Which failures are legitimate: the semantic rule

The steering rule (steering design, section 3): a supplied value must be a
possible output of its source and must not interact with an unsteered hidden
input. For an allocation the source is the allocator entry the C calls, and
the value is `{ok, fail}`. The strategy adds (section 3) that a steered
trace must remain an execution Linux can produce. The two are not the same
test for allocations, and the difference is the whole question.

**(a) `GFP_ATOMIC` and other non-reclaiming allocations** (`socket.c:192,
217`; `send.c:226`; every `pskb_expand_head` under `skb_cow_*`). The page
allocator returns NULL as soon as the watermark attempt fails: "Caller is
not willing to reclaim, we can't balance anything" → `nopage`
(`page_alloc.c:4462-4463`). The slab allocator's first slab-page attempt
adds `__GFP_NOWARN | __GFP_NORETRY` (`slub.c:2648`), its fallback to
`s->min` keeps the caller's flags (`:2655-2662`), and a `GFP_ATOMIC` caller's
flags do not reclaim, so `slab_out_of_memory` and NULL follow
(`:3925,4105`). NULL is an ordinary output under memory pressure, and a
trace that continues after it is an ordinary execution. **Steering within
the domain, no caveat.**

**(b) `GFP_KERNEL`-class allocations of at most `PAGE_ALLOC_COSTLY_ORDER`**
(`GFP_KERNEL`, `GFP_KERNEL_ACCOUNT`, `GFP_HIGHUSER`) — every other site in
section 2. The "too small to fail" rule, as the code has it: the slow path
retries direct reclaim while `should_reclaim_retry` allows
(`page_alloc.c:4493`, up to `MAX_RECLAIM_RETRIES` rounds without progress,
`:4161-4179`), then calls the OOM killer (`:4519`) and **retries whenever it
reports progress** (`:4530-4533`). `out_of_memory` reports progress when it
kills a task (`oom_kill.c:1181`), when the caller is itself exiting or
`SIGKILL`ed (`task_will_free_mem(current)` → `mark_oom_victim`,
`:1132-1136`), when the allocation lacks `__GFP_FS` (`:1143-1144`), and
panics when nothing is killable (`:1167-1177`). The only `nopage` exits for
this class are `__GFP_NORETRY` (`:4482-4483`), costly orders (`:4489-4491`),
and **the caller being an OOM victim with `ALLOC_OOM` or
`__GFP_NOMEMALLOC`** (`:4524-4527`; `ALLOC_OOM` is granted exactly to
victims, `:4108-4119,4138-4139`). Two sub-cases follow:

- **(b-task): the trace process's own syscalls** (14 of the 17 arms: the FS
  slice, the netlink peer and allowed-ips sites, every pipe site). NULL is
  in the output set — once `current` is an OOM victim, which means it has
  `SIGKILL` pending or is exiting (`task_will_free_mem`, `:875-885`;
  `mark_oom_victim` needs `tsk->mm`, `:755-773`). A victim does not run its
  next syscall. So **the value is in the output set, but the forced trace —
  the process receives `-ENOMEM` and goes on — is not a possible Linux
  execution**. That is exactly the status of every `failslab`/`fail_nth`
  test the kernel's own developers run: a declared domain extension that
  exercises arms the C has and real callers must handle (`failslab.c:27-32`
  skips only `__GFP_NOFAIL` and, by default, reclaiming allocations). The
  forced failure interacts with no other hidden input (clocks, draws,
  scheduling untouched; the only state it touches is the allocator's, below
  every cut). **Decision for the user, Q1**, with three options: class (a)
  only; (b-task) as a declared failslab-style extension, tagged per trace
  class (`alloc_fail`); or record-only for (b-task).
- **(b-kworker): `noise.c:100`**, `GFP_KERNEL` in the handshake receive
  worker. A kthread cannot be an OOM victim: `oom_unkillable_task` excludes
  `PF_KTHREAD` (`oom_kill.c:164-170`), and `mark_oom_victim` and
  `task_will_free_mem` need `tsk->mm` (`:755-773,875-885`), which a kthread
  lacks. `out_of_memory` then either kills a user task and the allocation
  retries, or panics (`:1167-1177`). **The output set is `{ok, panic}`**:
  NULL is not in it, and a forced NULL fails the rule's first clause, not
  only the execution clause. **Record-only.** The user may still declare it
  an explicitly out-of-domain steer to exercise `begin_session`'s failure
  arm (**Q2**); the design does not recommend it.

**(c) `kvmalloc`** (`file.c:152,157`): the slab attempt carries
`__GFP_NORETRY` above `PAGE_SIZE` (`util.c:620-624`) and so fails
genuinely; below it, (b-task) applies. Steerable where one slab call decides
the outcome (section 2.1); above `PAGE_SIZE` the slab failure is followed by
a successful `vmalloc`, so the record never means `-ENOMEM` (section 6.2).

**(d) Not allocations**: `access_ok`, the user copies, `skb_to_sgvec`. The
rule does not apply; sections 6.4-6.5 say what replaces their `envOk`.

**`__GFP_NOFAIL` is never forced** (M2), as `failslab.c:27-28` and
`fail_page_alloc.c:32-33` have it: the hook records and never fails such an
allocation, whatever the schedule says; the host refuses to build such an
entry; a negative control checks the kernel side (section 7). No site in
section 2 carries it.

**What a forced failure does not do.** The slab hook fails before any object
is taken (`slub.c:4215-4217`); the page hook fails before `prepare_alloc_pages`
and the free lists (`page_alloc.c:4830-4832`), and `warn_alloc` is reached
only via the slow path's `fail:` label (`:4571-4572`), so there is no console
dump. Helper-internal side effects of a failure (`__alloc_skb` frees the
`sk_buff` it got, `skbuff.c:711-712`; `__d_alloc` frees the dentry on an
external-name failure) are below the cut and in unanchored files.

## 4. Capture

### 4.1 Where: two allocator entry points, no config change

The strategy named `should_failslab`, `should_fail_alloc_page` and the
usercopy hook. They mark the right **places** but are the wrong **functions**:
without `CONFIG_FAILSLAB`/`FAIL_PAGE_ALLOC` they are inline stubs
(`fault-inject.h:116-132`), and with them they are the debugfs facility
(`failslab.c:19-47`, `fail_page_alloc.c:26-45`) whose `_RET_IP_` is useless
(`failslab.c:46` for every allocation). And they sit **inside** helpers that
the bulk allocators share: `slab_pre_alloc_hook` is called by
`kmem_cache_alloc_bulk_noprof` (`slub.c:5069-5078`) and `prepare_alloc_pages`
by `alloc_pages_bulk_noprof` (`page_alloc.c:4695`); a hook there would run a
pre side for bulk allocations that never see a post (C2a), and both bulk
paths are reachable (`napi_skb_cache_get`, `skbuff.c:349`, via `__alloc_skb`
`:669`; `vm_area_alloc_pages`). A therefore adds its calls in the two
**non-bulk entry functions**, with an explicit `addr`, in files the check
does not anchor (`correspondence/kcov.json` anchors `drivers/net/wireguard/*`,
the FS files and some headers; not `mm/*`):

- **Slab: `slab_alloc_node`** (`slub.c:4209-4237`), which has `addr`
  (`_RET_IP_` of the exported entry, or the explicit `caller` of
  `__kmalloc_node_track_caller_noprof`, `:4386-4392`). Before
  `slab_pre_alloc_hook` (`:4215`): `if (kcov_alloc_pre(&ctx, addr, flags &
  gfp_allowed_mask, orig_size)) return NULL;` — a forced failure **writes
  its record from the pre side** (C2b: the existing early return at
  `:4216-4217` never reaches a post) and returns. After `slab_post_alloc_hook`
  (`:4234`): `kcov_alloc_post(&ctx, object != NULL)` writes the record for
  every other case. `kmem_cache_alloc_bulk_noprof` and `slab_pre_alloc_hook`
  are untouched: **bulk is unhooked by construction**, a stated gap (no
  modeled path uses it; the NAPI skb cache does, outside our sites).
- **Pages: `__alloc_pages_noprof`** (`page_alloc.c:4805-4867`). After
  `current_gfp_context` (`:4820-4827`) and before `prepare_alloc_pages`
  (`:4830`): `kcov_alloc_pre(&ctx, _RET_IP_, gfp, order)`, forcing by
  writing the record and returning NULL; at `out:` (`:4856`) and the
  `MAX_PAGE_ORDER` early return, `kcov_alloc_post(&ctx, page != NULL)`.
  `_RET_IP_` here is the caller of `__alloc_pages_noprof`; with no NUMA the
  inline `alloc_pages_noprof` → `alloc_pages_node_noprof` chain
  (`gfp.h:294-301,315-318`) puts that address in the consumer.
  `prepare_alloc_pages` and `alloc_pages_bulk_noprof` are untouched. The
  slab allocator's own slab pages (`slub.c:2474,2631-2662`) reach this hook
  from `slub.c` addresses that are never armed, so a slab refill is
  invisible in armed mode and a forced slab failure is the single outcome
  the hook presents (section 4.3 says what inventory mode does with them).
- **Usercopy.** Not hooked (section 6.5).

Both files are `KCOV_INSTRUMENT := n` (`mm/Makefile:24-25`), so the hooks
add no coverage PCs; `kcov.c` is too (`kernel/Makefile:35`). The hook
functions live in `kernel/kcov.c` with `include/linux/kcov.h` declarations
and `!CONFIG_KCOV` stubs, as `kcov_choice_ip` does (`gen-choice-stream.py`).
**Oracle change:** `mm/slub.c`, `mm/page_alloc.c`, `kernel/kcov.c`,
`include/linux/kcov.h`, `include/linux/sched.h` (one per-task word). No
`.config` change; section 8 weighs the config-only alternative.

### 4.2 Identity: the slab-level address plus an unwound chain

A record's site is its **consumer frame**, as for every choice (strategy
4.2): the first frame of the symbolized chain outside the helpers. For
allocations the entry point's `_RET_IP_` (`addr`) reaches the consumer only
for the *direct* sites of section 2 — the inline `kmalloc`/`kzalloc`/
`kmem_cache_zalloc`/`kcalloc`/`alloc_page` wrappers, which `addr2line -i`
unfolds through `slab.h`/`gfp.h`. For the *helper* sites (`__alloc_skb`,
`pskb_expand_head`, `__d_alloc`, `alloc_inode`, `__kvmalloc_node_noprof`)
`addr` is inside `net/core/skbuff.c`, `fs/dcache.c`, `fs/inode.c` or
`mm/util.c`, one to three real frames below the consumer.

So the record carries a **chain**: `addr` as the record's call site, and up
to four return addresses above it from `stack_trace_save(buf, 4 + skip,
skip)` (`kernel/stacktrace.c:112-125`, `arch_stack_walk` on `current`, ORC;
exported GPL). The host symbolizes each address with its inline chain and
takes the first frame outside `CHOICE_HELPERS ∪ ALLOC_HELPERS`, where
`ALLOC_HELPERS` is a declared list of **files and functions**:
- files: `include/linux/slab.h`, `include/linux/gfp.h`, `mm/slub.c`,
  `mm/page_alloc.c`, `mm/util.c`, `net/core/skbuff.c`,
  `include/linux/skbuff.h`, `fs/dcache.c`, `fs/inode.c`;
- functions, by address range from `System.map`: `skb_checksum_help`
  (`net/core/dev.c:3378-3432`). Without it the `skbChecksumHelp` site's frame
  would be `dev.c:3421`, the `skb_ensure_writable` call, and not `send.c:188`
  (M3). Function ranges keep the rest of `dev.c` attributable.

P adds nothing: pipes' helpers are these. Every site in section 2 has its
consumer within depth 3 of `addr` on the expectation that `kmalloc_reserve`
and `__d_alloc` are out of line and `alloc_inode` is inlined into
`new_inode_pseudo`; A0 confirms this per site, and if a chain is cut short
the depth rises to six by raising `KCOV_CHOICE_MAX_WORDS` from 5 to 7 (the
guest's `n > 5` checks, `harness/guest.c:308,322`, move with it).

The strategy's note "two frames up ... passed explicitly or recovered" is
resolved as **recovered by unwinding**, gated (4.3), rather than passed:
passing the caller down would mean a parameter or a per-task slot set at
each helper's entry, i.e. a hook per helper file, which is the per-site
design the strategy retired and would fail the zero-new-hooks test for
pipes.

### 4.3 Gating: the armed allocation set, and inventory mode

Allocations are hot; recording every one in a recording context would flood
the stream with below-cut records (the fixture's `sendto` allocates skbs in
the trace task's context, ICMP replies allocate in NET_RX sections, netlink
allocates reply skbs). The hook therefore does, in this order:

1. `if (!READ_ONCE(kcov_alloc.armed)) return false;` — one load when no
   trace is armed. The set is loaded by the guest's parent before the fork
   with `KCOV_LEANUX_ALLOC_LOAD = _IOW('c', 205, unsigned long)` (next after
   D3's 204), argument `{u32 n; u32 flags; struct {u64 lo, hi;} ranges[n];}`:
   - `n = 0, flags = 0`: **disarmed, no records** — what every trace gets
     until the phased flip of section 6.6 (M8);
   - `n > 0`: armed with these ranges;
   - `flags & KCOV_ALLOC_INVENTORY`: **inventory mode** (A0): every
     candidate in a recording context is recorded, no steering.
   Disarmed with the dispatch set in `kcov_remote_reset`.
2. the recording-context test (`check_kcov_mode`, `kcov.c:170-185`): not in
   a trace's task or sectioned softirq → return.
3. **range membership**: `addr` within one of up to 64 `[lo, hi)` ranges
   the host resolved: for a direct site, the return addresses of the
   consumer's calls into the allocator entry points (`lo = hi − 1`, as
   `harness/steer.py:call_sites` finds call sites today, extended to the
   slab and page entry symbols); for a helper site, the **helper function's
   whole range** (`__alloc_skb`, `kmalloc_reserve`, `pskb_expand_head`,
   `__d_alloc`, `alloc_inode`, `__kvmalloc_node_noprof` from
   `System.map`/`objdump`), so that any allocation inside the helper is a
   candidate. Sorted ranges, binary search: six compares. Lock-free, a
   `READ_ONCE` snapshot like D3's `kcov_timer_arm`; the set changes only
   while no trace runs.
4. only then the unwind, the steering match (section 5) and the record.

**Below-cut candidates.** A candidate from a helper range whose chain
reaches no declared consumer is still recorded: the check attributes it by
chain, and it is either a declared **cut consumer** (strategy section 5) or a
`hidden_mismatch`. The audit's expectation, which A0 confirms or corrects, is
four to six consumers, all through `__alloc_skb`: the fixture's own `sendto`
(`__ip_append_data`), netlink replies and dumps (`netlink_alloc_skb`), and
ICMP (`icmp_send`), each consumed at its cut point by `skipCut` with a
stated reason its outcome cannot reach mirrored state. If the list proves
unbounded, the fallback is a per-trace dropped-below-cut counter in the
status ioctl, reported not failed — a weaker rule, named as such. **Q4.**

**Inventory mode** (A0) is a mode of the real hook, not a throwaway kernel:
with `KCOV_ALLOC_INVENTORY` set, step 3 is skipped and every candidate in a
recording context is recorded. It runs in **two passes**: first counting by
`addr` only (no unwind, word 1 holds a zero chain), which is cheap enough for
every allocation; then with chains, but only for candidates whose `addr`
symbolizes into an inventory file (the host passes those `addr`s as the
ranges, with the flag), which bounds the unwind cost to the sites under
study. **Nested records**: a slab refill (`new_slab` → `alloc_slab_page` →
`__alloc_pages_noprof`, `slub.c:2631-2662`) fires the page hook inside a slab
allocation's pre/post window. In inventory mode the page record is written
with a **refill bit** in word 0 and no chain (the re-entrancy depth guard
`t->kcov_leanux_in_alloc` marks it, rather than suppressing it), so the
report counts refills separately; in armed mode `slub.c` addresses are never
armed and no nested record exists.

### 4.4 The record: kind 305

`kcov_choice_write(t, 305 | steered, addr, payload, 40)`, five words:

| Word | Content |
|---|---|
| 0 | bits 0-7: outcome (`1` ok, `0` NULL); bit 8: refill (inventory mode only); bits 9-31: `orig_size` (slab) or `order` (page); bits 32-63: the gfp mask as the hook saw it — after `gfp_allowed_mask` on the slab path (`slub.c:4133`), after `gfp_allowed_mask` and `current_gfp_context` on the page path (`page_alloc.c:4820-4827`) |
| 1-4 | the unwound return addresses above `addr`, innermost first, zero-padded |

A forced failure's record is written from the pre side with `ok = 0` and
the steered bit; every other record is written after the allocator returns,
so the outcome is Linux's actual one: a natural NULL (class (a) under
pressure, or the `__GFP_NORETRY` slab attempt of an 8 KiB `kvmalloc`) is
recorded as `ok = 0` with the steered bit clear. The sequence number orders
it with every other record. In comparison mode the header-plus-payload
layout is as for other kinds (`gen-choice-stream.py`, `kcov_choice_write`).

The mirror consumes word 0's outcome; the check uses the whole payload for
attribution and the gfp/size for the inventory report (per site: counts, gfp
classes, forced vs natural). The steered-value check compares only the
outcome byte of word 0 for kind-305 entries (section 5.3).

### 4.5 Context and locking

- The hooks run before the slab takes any lock and before the page
  allocator's zone locks; `kcov_choice_write` and `stack_trace_save`
  allocate nothing. Interrupts may be disabled (GFP_ATOMIC in softirq), as
  for the clock hooks today.
- **`kcov_remote_lock`.** The steering lookup for the trace process's own
  context takes `kcov_remote_lock` (`kcov_steer_find`, patched `kcov.c`).
  `kcov_remote_add` allocates **under** that lock (`kcov.c:660`,
  `kmalloc(GFP_ATOMIC)`) — in the parent's `KCOV_MODE_REMOTE` (`:647`, set
  before the loop), which step 2 rejects, and from a `kcov.c` address step 3
  never arms. On this `!SMP` kernel the hazard is moot in any case: spinlocks
  are preempt- and irq-disable only, so a nested acquisition cannot
  deadlock. The gating order is kept for portability and as a review item,
  not as a risk.
- Timer sections (D3): a keepalive's `alloc_skb` inside
  `wg_expired_send_keepalive` is recorded in the timer section like any
  other choice; the mirror's callback consumes it.
- Per-task state: `struct kcov_alloc_ctx` on the stack between pre and post;
  one new `task_struct` word, `kcov_leanux_in_alloc`, as the re-entrancy
  depth guard of 4.3.

## 5. Supply: steering a failure

### 5.1 Schedule entries for kind 305

The per-handle schedule (`KCOV_LEANUX_STEER_LOAD`, strategy 10d) gains
allocation entries: `kind = 305`, `len = 8` (word 0), `value = 0` for
**fail** or `draw` for "record whatever the allocator does", and `ips[4]`
holding **consumer-level** return addresses: the return addresses of the
consumer's call into the allocation entry or helper (after `call
__kmalloc_cache_noprof` in `do_eventfd`; after `call __alloc_skb` in
`wg_socket_send_buffer_to_peer`; after `call skb_cow_data` in the encrypt
worker; after `call d_alloc_pseudo` in `alloc_file_pseudo`). The host
resolves them as `steer.py:call_sites` does for the random and clock hooks,
with the allocator entries and the helper entry functions as targets, and
the tail-jump refusal unchanged.

**Encounters per consultation.** A schedule that names a site covers every
encounter of that site (steering design 4.1). For `__alloc_skb` a success is
**two encounters** whose chains both contain the consumer — the `sk_buff`
(`skbuff.c:671`) and then the data buffer (`:681`, from `skb_small_head_cache`
for these sizes, `:590-600`) — and a failed first encounter is one. The
generator emits two `draw`s for an untouched `alloc_skb`, `fail` alone to
fail the `sk_buff`, or `draw, fail` to fail the data buffer and reach
`nodata` (`:711-712`) (M6). The placeholder run predicts this from the site's
declared count (section 6.2).

### 5.2 Matching in the kernel

`kcov_steer_apply` today matches `ip == e->ips[j]`, twice: once to decide
whether the site is **named at all** (`kcov_steer_names`, patched
`kcov.c`; `gen-choice-stream.py:93-103,116`), then against the head entry.
For `kind == 305` **both** tests use chain containment: an entry names the
encounter when some `ips[j]` equals `addr` **or any of the unwound return
addresses**. If only the head-entry test were chain-aware, a helper site's
encounter would fail the naming test on `addr`, return "not steered" with no
marker, and the site would silently never be steered — fail-open (M4). The
entry's `pad` word becomes `flags`, bit 0 = chain match. A direct site
matches on `addr`; a helper site on the consumer's frame above it. A named
encounter that does not match the head entry is the existing mismatch
(`0xffff` marker, `mismatches++`).

On a `fail` match, `kcov_alloc_pre` writes the record (`ok = 0`, steered) and
returns true; `slab_alloc_node` or `__alloc_pages_noprof` returns NULL
(section 4.1). An entry with `__GFP_NOFAIL` in the allocation's flags is
never applied: the encounter is recorded as drawn and the entry **stays**,
so the parent sees it as a leftover — fail-noisy, never fail-open (M2).

### 5.3 The exact check, extended

`steering_problems` (`evaluator/check.py:321-346`) compares `(label,
steered, value)` per entry. For allocation entries the value compared is the
outcome byte of word 0 (the chain words are build-specific and belong to
attribution, not to the schedule). Everything else holds: leftovers and
markers are problems, an unreached site fails, an extra entry fails.
`expect` labels name the failure arm (`wg_peer_create.no_mem=1`), so a hook
that forces nothing is caught twice: by the exact check (not steered) and by
the unreached expectation.

### 5.4 Domain mode

The domain filter runs the mirror with placeholders before Linux
(`Defs.lean:hidden`, `hiddenPlaceholders`). An allocation placeholder is `ok`
unless `steerValues` holds the site's label, in which case it is the
schedule's value for that encounter — the mechanism that exists for clocks
and draws (`:530-544`). The generator predicts the encounters from the
placeholder run and emits the schedule, as for D1 (steering design 6.3).

### 5.5 What the host refuses (M5)

`STEERABLE` in `harness/steer.py:33` is a flat set today. For allocation
sites it becomes a table, one row per site, carrying the class of section 3,
exact or lax, and the encounter count A0 fixed per trace class. `resolve`
refuses a `fail` entry when:
- the site's class is not enabled for the run ((a) always; (b-task) only
  under the user's extension, Q1; (b-kworker) only under Q2);
- the site is lax and A0 fixed no count for the trace's class;
- the site's allocation carries `__GFP_NOFAIL` (none today);
- the site is the 8 KiB `kvmalloc` (section 6.2).

A refused schedule is a `SteeringError` before anything reaches the guest.

## 6. The mirror

### 6.1 `envOk` becomes a hidden choice

`EnvSite` is folded into `HiddenSite`: a constructor `.alloc (s : AllocSite)`
with `info = ⟨70 + s.index, s!"alloc:{label}", "alloc", file, line, 40,
role⟩`, one entry **per consumer frame** (strategy 4.2): the shared
`allocSkb` splits into `sendBufSkb` (`socket.c:192`), `replySkb`
(`socket.c:217`, E) and `keepaliveSkb` (`send.c:226`); `kmemCacheZallocNode`
into three (`allowedips.c:190,205,234`), with `allocNode` taking the site.
**Ids 70-99 are reserved for A now** (M8): today's ids run to 63 (the section
sites, `Defs.lean:327-328`, reach `41 + 2·5`), and D3 adds its worker and
timer sites below 70. `load_hidden_sites` (`check.py:196-212`) admits kind
`alloc` (and D3's `timer`). `envOk` is replaced by

```lean
/-- An allocation outcome (kind 305) at this consumer frame: `ok`, or the
    failure arm. Exact sites consume the declared number of records; lax
    sites consume the records of this site at the head (zero or more) and
    fail if any failed. Unarmed runs (section 6.6) answer `ok`. -/
def hiddenAlloc (s : AllocSite) : M Bool
```

`World.env`, `envCalls` and `harnessEnv` (`Defs.lean:404-406,495-499`,
`Runner.lean:345,379`) go. In an armed run a missing record is `.hidden "no
record supplied for alloc:..."`, as for every site; an unexpected one fails
at the next read or the operation's end (`Runner.lean:executeTrace`).

### 6.2 Exact and lax consumption

- **Exact** (a declared count per consultation): every direct site (1);
  `__alloc_skb` sites (2 on success: the `sk_buff` record, then, if ok,
  exactly one data record; 1 on a failed `sk_buff`); `d_alloc_pseudo` (1);
  `alloc_inode` (1); `kvmalloc` below `PAGE_SIZE` (1).
- **Lax** (zero or more records, outcome = all ok): `skb_cow_head`,
  `skb_checksum_help`, both `skb_cow_data`s. Their allocation count depends
  on skb layout below the cut (section 2.3). Like the cut skip sets, this is
  weaker and is declared with its reason per site; unlike them, the recorded
  **outcome is used and checked**: a fail record forces the mirror into the
  failure arm, and a mirror that takes the arm without one disagrees with
  Linux (A1/A2). A lax site is steerable only for a trace class where A0
  shows a fixed count (section 5.5).
- **`kvmalloc` of the 8 KiB fd array** (`nr = 1024`): the site consumes the
  slab record. `ok` proceeds. A fail record at this size — natural (the
  `__GFP_NORETRY` attempt, `util.c:620-624`) or forced — means Linux went
  on to `vmalloc` and **succeeded**, so it must never select the `-ENOMEM`
  arm: the mirror answers `unsupported "kvmalloc vmalloc fallback"`,
  fail-noisy (M7). The host never schedules a `fail` here (5.5), and a
  control confirms the mirror's response to a natural one (section 7).

### 6.3 What the comparator stops absorbing

`SEMANTIC_ERRNOS` (`protocol.py:103-108`) gains `ENOMEM` (12) for `eventfd2`,
`dup3`, `fcntl`, `wg_set`, `write` (pipes) and `ENFILE` (23) for `pipe2`; a
Linux `ENOMEM` is then compared, not classified `environment_failure`. With
records, an `ENOMEM` the mirror did not take is a `semantic_mismatch` plus an
unconsumed or absent record: fail-noisy on both sides. The
`environment_failure` outcome stays for errnos no model explains.

### 6.4 Sites retired as not environment choices [AGENT]

- `skbToSgvec` (both): `branch .encSgvecFailed false` / `.decSgvecFailed
  false` with the reason "linear skb: `__skb_to_sgvec` returns 1" — a
  constant-outcome decision like `encTooManyFrags`.
- `idaAlloc`: `idaAlloc` returns the next id; `unsupported "ida bitmap
  allocation (id ≥ 63)"` if `idaUsed` ever reaches `BITS_PER_XA_VALUE`, which
  the per-trace process exit (`ida_free` on release) keeps far away.
- `dstCacheInit`: `branch .peerCreateDstCacheFail false` with the honest
  reason: the percpu allocator's inner allocations have a **state-dependent
  count** (they occur only when a chunk must be created, `percpu.c:1851-1855`),
  so the site would be lax, and lax with no fixed count is unsteerable. The
  arm stays dead, named.

### 6.5 The usercopy trio: trace inputs, not fault injection [AGENT proposal]

`access_ok`, `copy_to_iter` and `copy_from_user` failures are decided by the
user pointer, which the trace supplies. A `read`/`write` operation gains an
optional `buf: "kernel" | "unmapped"`: the guest passes a kernel-half address
(fails `access_ok`, `uaccess_64.h:56,98-105`: `vfs_read` returns `-EFAULT` at
`read_write.c:557`) or a `PROT_NONE` page in the user half (passes
`access_ok`, faults in the copy: `eventfd_read` `-EFAULT` at
`eventfd.c:241-242`, `eventfd_write` at `:256-257`). The mirror computes the
three decisions from the operation — program decisions on trace input, no
hidden choice, no kernel hook. `EFAULT` (14) joins `SEMANTIC_ERRNOS` for
`read`/`write`. This is the "natural inputs" criterion applied literally, and
it finishes the retirement of `harnessEnv`. It is a small separate stream
(A-U) and does not block A.

### 6.6 The phased flip (M8)

Every existing trace allocates at inventory sites (every `eventfd2`, every
handshake), so the moment the mirror demands kind-305 records, every corpus,
generated suite, mutant baseline and steering control needs re-recording on
the A kernel. To keep that from being a big bang:
1. the kernel records nothing unless armed (`n = 0`: section 4.3), so the A
   kernel can replace the oracle **before** any trace declares allocation
   sites and every existing run is unchanged;
2. the runner tells the mirror whether the run was armed (a per-run flag
   beside the records, `World.allocArmed`); `hiddenAlloc` is fail-noisy
   only when armed, and answers `ok` otherwise — the present behaviour,
   now explicit and logged per run as `alloc: unarmed`;
3. traces are armed suite by suite as they are re-recorded, the full check
   is run with every suite armed, and then the unarmed answer is removed:
   the flip is one commit, after the evidence.
The unarmed answer is a transitional fail-open, declared here, with its
removal in the plan (section 12); it never applies to a trace that declares
an allocation schedule.

**Traces** (`corpus/alloc/a_*.json`, `scripts/alloc-corpus.py`), each with

## 8. Kernel config, and the config-only alternative stated honestly (M9)

| Option | Needed? | Why |
|---|---|---|
| `CONFIG_FAULT_INJECTION`, `FAILSLAB`, `FAIL_PAGE_ALLOC`, `FAULT_INJECTION_USERCOPY`, `FAULT_INJECTION_DEBUG_FS` | **no** [AGENT] | see below |
| `CONFIG_STACKTRACE`, `UNWINDER_ORC` | already set | `stack_trace_save` |
| `CONFIG_KCOV*` | already set | |

**What the stock facility could do.** With `FAULT_INJECTION`, `FAILSLAB`,
`FAIL_PAGE_ALLOC` and `FAULT_INJECTION_DEBUG_FS` (`DEBUG_FS` is already on,
`:1964`), the filters are tunable at run time — `failslab/ignore-gfp-wait =
0`, `fail_page_alloc/ignore-gfp-wait = 0`, `min-order = 0`,
`ignore-gfp-highmem = 0`, `verbose = 0` (`failslab.c:66-69`,
`fail_page_alloc.c:58-62`) — and `/proc/self/fail-nth` makes the n-th
allocation of the writing task fail exactly once (`fs/proc/base.c:1436-1460`,
`lib/fault-inject.c:109-118`, `sched.h:1400`). That is a **config-only
oracle change** that reaches all 14 (b-task) arms with no kernel patch. What
it does not give:
- **capture**: no record of any allocation outcome, so the mirror would
  still assume `ok` everywhere and a `fail-nth` trace would have to tell the
  mirror out of band which allocation failed — a supplied value with no
  recorded witness, the inverse of the strategy's rule that supplied entries
  are still recorded;
- **identity**: `fail-nth` counts allocations, it does not name them; the
  n-th allocation of a syscall is a property of this build and of kernel
  state (slab refills, `ida` growth), and nothing checks the count landed on
  the intended site;
- **the worker and softirq sites**: `fail_nth` is honoured in task context
  only, so class (a) — the three `GFP_ATOMIC` `alloc_skb` sites in kworkers
  and timer softirqs, and every `skb_cow_*` site — is out of its reach.

So A's justification is **capture plus the worker and softirq sites**, not
"the stock facility cannot fail GFP_KERNEL". If the user wants the (b-task)
arms exercised before A's kernel exists, `fail-nth` with the debugfs knobs
is the quick, uncaptured way, and nothing in A conflicts with trying it.

The oracle change for A is the patch alone: the two allocator entry
functions, the hook and the ioctl in `kcov.c`, the header, the per-task
word. The identity file (`kernel/identity-x86_64-net-choice.txt`) records it
as for step 1 and D3.

## 9. Noise and performance

- **Unarmed** (between traces, the guest's own work, and every trace until
  the flip): one load per allocation.
- **Armed, non-recording contexts**: plus `check_kcov_mode` (two loads and a
  branch). Every allocation in the guest pays this during an armed trace.
- **Armed, recording contexts**: plus the range search (six compares over at
  most 64 ranges). The trace process's syscalls and the sectioned workers
  allocate tens to a few hundred objects per operation; this is within the
  noise of the TCG VM.
- **Candidates**: the unwind (ORC, four frames; a few microseconds native,
  plausibly tens on TCG — measured in A0) and an eight-word record. Per
  trace: FS, one to six per operation; WireGuard, two to ten per handshake
  or packet; below-cut candidates from the helper ranges, a few per
  operation. Under 500 records per trace, under 4,000 words of the
  65,536-word areas (`guest.c:31`, `CAPACITY`), with the dropped counters as
  the guard.
- **Inventory mode** (A0): the first pass costs the record alone for every
  allocation in recording contexts (no unwind); the second pass unwinds only
  the inventory files' candidates. Both are compared against today's
  per-operation times.

## 11. Risks

- **Medium: the below-cut consumer list.** If the helper ranges surface many
  kernel paths that allocate skbs or dentries in recording contexts, the cut
  skip set grows and the attribution rule weakens toward a counter (section
  4.3). A0 decides; the mitigation is to arm narrower ranges
  (`kmalloc_reserve` rather than all of `__alloc_skb`, only when the chain
  can still be resolved).
- **Medium: unwinding cost on TCG.** Plausibly tens of microseconds per
  candidate; gated to candidates, so bounded by their count; measured in A0.
- **Medium: a forced failure's downstream behaviour is new C territory.**
  The failure arms have never run in this fixture; a kernel-side leak or
  oddity (for example `eventfd.c:401`'s unchecked `ida_alloc`) is real
  behaviour the mirror must follow, not a mirror bug. Each A trace's
  expectation is checked against Linux first (the Linux-only run of the
  corpus in K2).
- **Medium: the (b-task) semantic caveat** (section 3). A2 rests on the
  user's acceptance of a declared, failslab-style extension; A1 does not.
- **Low: chain depth.** Fixed at four words in the first build; raising it
  changes the record width and the guest parser.
- **Low: the transitional unarmed answer** (6.6) is a declared fail-open
  until the flip; its removal is a plan item, not optional.
- **Low: `KCOV_STEER_MAX` (64) and the range array (64).** Pipes plus
  WireGuard declare about 25 sites.
- **Negligible here: lock order** (4.5), kept for portability.
- **Sequencing.** The A kernel must contain D3's changes; every suite is
  re-recorded on it, armed, before the flip and the signoff.

  binary search of the canonicalized address over ≤ 64 sorted `[lo, hi)`
  ranges, or, with `n = 0` and `KCOV_ALLOC_INVENTORY`, every allocation.
- **Record**, kind 305, 40 bytes; word 1-4 the four return addresses above
  `addr`, found by `stack_trace_save` of 16 entries and a search for `addr`
  (robust to the inlined `slab_alloc_node` and to skip counts).
- **Nesting.** A depth counter per context (`task_struct.kcov_leanux_in_alloc`
  in task context, a per-CPU counter in softirq), so a softirq that
  interrupts a task's allocation is not marked nested.
- **Ioctls.** `KCOV_LEANUX_ALLOC_LOAD = _IOW('c', 205, …)`, `{u32 n; u32
  flags; {u64 lo, hi}[n]}`, validated (n ≤ 64, sorted, disjoint, `lo < hi`,
  flags ⊆ {inventory}); `n = 0, flags = 0` disarms. One owning instance
  (another instance's load is `-EBUSY`), disarmed in `kcov_remote_reset`
  (reached from `kcov_put` for every instance). `KCOV_LEANUX_ALLOC_STATUS =
  _IOR('c', 206, …)`: `{records, unwinds, unwind TSC cycles}` since the load
  (A0's cost measure).
- **Forced failures.** The pre-side path exists (`kcov_alloc_force` →
  record `ok = 0` with the steered bit, return true), with the
  `__GFP_NOFAIL` guard; `kcov_alloc_force` returns false in this build.
  Steering is K2's.
- **Harness.** Wire line `M FLAGS N lo hi …` after `A`
  (`harness/trace.py` `alloc_line`; `run_linux(..., alloc=)`, default `M 0
  0`). The guest skips the load when disarmed; armed, it prints
  `LEANUX_ALLOC` per trace and child and `LEANUX_ALLOC_TSC` once, which
  `harness/linux.py` requires iff armed (`alloc.jsonl`).

**Disarmed check on the K1 kernel** (`LEANUX_KERNEL_DIR=…/kernel-net-choice-a`,

### 16.3 Deviations from the design [AGENT]

- **Word 0 layout:** bit 9 = page allocator, bit 10 = unwind did not find
  `addr`, the size/order in bits 11-31 (21 bits, saturating), instead of
  bits 9-31. The host needs the page bit to read the size field, and the
  miss bit keeps a failed unwind visible.
- **Where the set is loaded:** by the trace process on its own KCOV
  descriptor, after `KCOV_INIT_TRACE` and before `KCOV_ENABLE`, not by the
  parent on the remote descriptor. FS traces have no remote instance, so
  this is one path for both. The set is armed before any recorded work and
  disarmed with that instance.
- **Disarmed = no ioctl:** with `M 0 0` the guest does not call 205, so
  existing runs do exactly what they did, also on older kernels.
- **Status ioctl 206:** added for A0's unwind cost.
- **Page-path post:** the design names the `MAX_PAGE_ORDER` early return.
  The pre runs after it, so the post is on the `prepare_alloc_pages` failure
  return instead. The slab `slab_pre_alloc_hook` NULL return also posts (a
  natural NULL, recorded).
- **Nesting counter per context** (task, or per-CPU softirq) instead of the
  task word alone.

### 17.5 What A1 and the mirror/harness/corpus streams need from K2

**The kind-305 record** (unchanged from K1, section 4.4): 40 bytes, five
little-endian u64 words. Word 0: bits 0-7 outcome (1 ok, 0 NULL); bit 8
nested (refill); bit 9 page allocator (then the size field is the order);
bit 10 the unwind missed; bits 11-31 `orig_size` (slab) or order (page),
saturating; bits 32-63 the gfp mask. Words 1-4: up to four unwound return
addresses above `addr`, innermost first, zero-padded. The record's call site
(header word) is `addr`. A forced failure's record has the steered bit
(`305 | 0x8000`) and outcome 0.

**The mirror** (`hiddenAlloc`, section 6): consume **word 0's outcome byte**
only; the gfp/size/chain are attribution, not model input. The
site-to-consumer map is section 16.2.2; ids 70-99. `World.allocArmed` is
true for a batch the runner armed (the evaluator arms a chunk iff it holds a
steered allocation site). The lax D2 sites consume **zero** records on this
fixture (count fixed at 0, section 16.2.3): `hiddenAlloc` for them is a
constant `ok` with a stated reason, not a consumed choice. `skbCowDataTx`,
`skbCowHead`, `skbChecksumHelp`, `skbCowDataRx` are record-only at count 0.

**The steering schedule** (the trace's `steer` list, resolved by
`harness/steer.py resolve`): an allocation label's entry becomes
`(305, 8, draw, ips, hex, flags)` — `draw` or the eight-zero-byte fail value,
`ips` the consumer's return addresses (a direct site's call into the
allocator; a helper site's call into the helper), `flags = KCOV_STEER_CHAIN`
for a helper site. The evaluator arms that chunk with `alloc_ranges(...)`
(the direct sites' `[ip, ip+1)`, the helper sites' whole helper ranges;
`flags = 0`, i.e. not inventory). The wire `S` line now carries the flags
field: `S kind len draw flags ip0 ip1 ip2 ip3 [hex]`.

**The steerable sites for A1** are `sendBufSkb` (`socket.c:192`), `replySkb`
(`socket.c:217`, E) and `keepaliveSkb` (`send.c:226`); each a helper site
(`__alloc_skb`), exact count 2 (fail the `sk_buff` with one `fail`, or the
data with `draw, fail`). The generator (`generate.py`, stream H) emits two
entries per untouched `alloc_skb` success, one `fail` to fail the `sk_buff`,
or `draw, fail` for the data buffer (M6).

**Comparator** (`SEMANTIC_ERRNOS`, section 6.3): still needs `ENOMEM` for
the steered sites so a Linux `-ENOMEM` is compared, not absorbed. For A1 the
`alloc_skb` failures produce no `-ENOMEM` at the syscall (the sends are in
workers or staged), only a missing datagram, so A1 does not depend on the
`SEMANTIC_ERRNOS` change; A2 does.
