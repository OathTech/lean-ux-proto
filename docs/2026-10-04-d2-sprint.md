## 1. Target

As in the design, section 1. Payload packets in both directions are checked
against Linux:
- **behavior:** the ciphertext at the fixture, the delivered inner datagram
  with its source, `rx_bytes`, and the receive error counters;
- **control flow:** over all of it, with the decrypt worker and the NAPI
  poll ordered by records;
- **operands.**

Outside the domain: the design's section 8.

## 3. Shared interfaces (commit on `task/d2`, the base of every stream)

- **Types** (`Leanux/WG/Types.lean`):
  - `Packet` (bytes, `csum` as (`csum_start`, `csum_offset`) or `none`,
    `mtu`);
  - `Peer.staged : List Packet`;
  - `DataPacket.plaintext : Packet`;
  - `ReplayCounter` (`counter`, `backtrack`: 128 words) and
    `Keypair.receivingCounter`;
  - `RxPacket` (peer, keypair, nonce, bytes, state, source);
  - `Peer.rxQueue`, `napiScheduled`, `timerNewHandshakePending`,
    `timerSendKeepalivePending`, `timerNeedAnotherKeepalive`,
    `sentLastminuteHandshake`;
  - `Device.rxErrors`, `rxFrameErrors`, `rxLengthErrors`, `decryptLastCpu`,
    `decryptQueue`.
- **Inbox** (`Leanux/Kernel/Defs.lean`): `InboxDatagram` (family, addr,
  port, bytes) for `World.senderInbox`. Both wg0's own datagrams and
  delivered inner packets land there.
- **Workers and sites** (`Defs.lean`):
  - `Worker.decryptWorker` (symbol `wg_packet_decrypt_worker`, index 5,
    section sites 50/51), in the armed dispatch set
    (`harness/linux.py`);
  - `HiddenSite.reschedDecrypt` (id 63, `receive.c:505`);
  - `HiddenSite.newHandshakeJitter` (id 16, `timers.c:150`, 1 byte; the
    consumer frame is TO-CONFIRM in this build, by stream A);
  - `Env.sectionOf` includes the decrypt worker.
- **Timers** (`Leanux/WG/Handshake.lean`, used by both mirror streams):
  - `modPeerTimer` returns whether the timer was armed;
  - `jitterBelowRekeyTimeout site`;
  - `timersDataSent` (pending test, jitter, arming);
  - `timersDataReceived` (running, pending, need-another-keepalive);
  - `timersAnyAuthenticatedPacketSent` / `…Received`, which clear the pending
    flags, are already called on the handshake and keepalive paths;
  - `timersHandshakeComplete` resets `sentLastminuteHandshake`.
- **Transmit input** (`Leanux/Runner.lean`, `Leanux/Syscalls.lean`):
  - the `wg_xmit` operation's packet object gains an optional `payload`
    (lowercase hex, 1 to 1392 bytes), whose absence means the historic
    `"leux"`;
  - `Env.xmitPacket family addr payload : M Packet` is an **interface stub**
    (lengths only) that stream A replaces.
- **Decision table** (`Leanux/Kernel/Decision.lean`): each stream adds
  constructors in its own block (comments `-- D2 stream A` / `-- D2 stream
  B`), and its labels in the list of all decisions, to keep merges additive.
- **The observation format** (`wg_observe`) is owned by stream A: the guest
  side, the parse in `harness/linux.py` and `Env.wgObserve`.

### 6.1 The target

Payload packets in both directions are checked against Linux.

**Transmit:**
- payloads after a session, and staged lists flushed by a session (1–4
  packets);
- padding, including the MTU clamp (payloads 1, 15, 16, 17, 20 and
  1376–1392);
- the completed inner checksum.

The ciphertext at the fixture equals AEAD over the environment's predicted
inner packet. Stream A also decrypted Linux's ciphertexts offline and
compared them with that packet.

**Receive:**
- the decrypt worker, the replay window (RFC 6479, including the boundary
  pair N−8128 / N−8129 and partial word clears), the counter limit, tampered
  tags;
- dishonest type, size and source;
- keepalives;
- inner IPv4/IPv6 datagrams delivered to the sender socket, with their
  sources;
- roaming;
- the responder's confirmation (`received_with_keypair` promoting next to
  current, which flushes staged packets through the encrypt and tx workers).

### 6.3 What the sprint found [AGENT]

**The design audit (before code):**
- **C1, critical:** the fixture's default `IP_PMTUDISC_WANT` makes Linux draw
  a jiffies-based IP id. Fixed with `IP_PMTUDISC_DO` on the sender, which
  stream A's control confirmed: under WANT, Linux's ids differ.
- **M1:** `napi_schedule` from the decrypt worker wakes ksoftirqd, so the
  poll has three placements. Both observable ones occur, as the counts
  above show.
- **M2–M4:** timer state and jitter, and the receive-side `keep_key_fresh`.
- **M5:** the one fail-open item, an inner-delivery rule wider than Linux's.
  It was replaced by an exact predicate, with everything else `unsupported`.

**Integration:** stream A extended crypt queues to one entry per ring item
and anchored the ECN headers. Stream B carried the outer DS field. An
observation slip (the type of a short reply) was fixed.

**The independent review** found no critical defect. It confirmed the
correspondence point by point and found the delivery rule fail-closed.
Fixed:
- **M1, systemic across the mirror:** a Lean panic (an out-of-range `!`)
  printed `index out of bounds` and continued with a default value, and the
  check read only the exit code. Now any stderr output from a run that
  exits 0 is a mirror invariant failure, and the replay bitmap is
  bounds-checked. No run of any worktree had panicked, so no false
  agreement is retracted. The bitmap mutant D2-M2 had been rejected only
  through that fallback.
- **M2:** D2-M12, the poll-placement control, is rejected only when a run
  shows order (b/c). `evaluator/napi_orders.py` counts the placements, and
  a pass without one is reported as inconclusive.
- **Minor:**
  - `ds` reaches the send cut;
  - the IPv6 payload bound is checked at validation;
  - partial-clear replay traces were added;
  - the environment assumptions of the delivery rule are stated;
  - the QEMU-slot wait is logged.
- **One review correction was reverted:** the `vlan_type` decision line
  must be a statement in this build (612, not 609).

**Integration harness:** the Linux runner now waits for the shared QEMU
slot (up to an hour) instead of failing with `resource_busy`.

### 6.4 Open, as follow-ups

- **Timer firing and key expiry:** D3.
- **Full-MTU receive:** `wg_inject` caps messages at 1400 bytes.
- **The `DEAD` break of a multi-skb item:** mirrored, but never exercised
  (the environment oracle never fails an allocation; roadmap step 5).
- **IPv6 inner packets with a zero UDP checksum, and unusual IPv6 sources:**
  `unsupported`.
- **H-M11 is obsolete.** It is the negative control "cut records in an
  operation without its cut point (wg_xmit)", and it now passes. D2's fixture
  change (`IP_PMTUDISC_DO`, IPv4 id 0) removed the ident draw it relied on:
  `Env.fixtureSend`'s cut now consumes no record on the xmit path, so the
  mutant is equivalent. Proposed [AGENT]: retire it, or retarget it to an
  operation that still draws at a cut. Raised with the user at signoff.
- **D2-M12 and D1-M15 depend on timing:** their verdicts carry the counts
  that make them conclusive.
