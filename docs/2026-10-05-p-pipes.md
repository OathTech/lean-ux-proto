# P: pipes, stage 1 — the scale test — design, 2026-10-05

Status: **draft for user review** [AGENT 2026-10-05]. Follows the
[reconnaissance](2026-10-05-pipes-reconnaissance.md) (verdict: zero new
kernel hooks) and the roadmap's step 7 ("the next subsystem needs only
declarations", [choice-stream strategy](2026-10-03-choice-stream-strategy.md)
section 10). The template is the [D2 data-plane note](2026-10-04-d2-data-plane.md).
Kernel paths are under `.deps/linux` (6.12.110); the guest config is
`kernel/config-x86_64-net-choice`. Every kernel claim below carries its
`file:line`; the ones I could not settle from source are listed in section 10
and in the final report.

**What stage 1 claims.** Anonymous pipes (`pipe2`, `read`, `write`, `close`,
`dup`/`dup3`, `fcntl`) on one CPU, checked against Linux for behavior (A1:
results, bytes, the two descriptors, SIGPIPE), control flow (A2) and operands
(A3), with **no kernel change**: the only hidden input, the coarse real-time
clock read by `current_time` (`fs/inode.c:2648`), is declared as one mirror
site and consumed where the C consumes it. Its values flow into the pipefs
inode's timestamps and decide later branches (`timespec64_equal`,
`include/linux/time64.h:49`), which A3 checks operand by operand. That is the
generic-capture claim under test.

## 3. The clock

**One new site.** `HiddenSite.currentTime`:
`⟨18, "current_time", "clock", "fs/inode.c", 2648, 16, .mirror⟩`. The hooked
reader is `ktime_get_coarse_real_ts64` (kind 215, 16 bytes: `tv_sec` then
`tv_nsec`, little-endian `s64`s); its consumer frame is `current_time`
(`fs/inode.c:2644-2650`), the first frame outside the clock helpers. All
five callers share this site, which the choice-stream design accepts
(section 4.2: records are consumed in sequence order). [AGENT] Alternative,
not recommended for stage 1: add `current_time` and
`inode_set_ctime_current` to `CHOICE_HELPERS` (`harness/steer.py`) to get
one site per consumer; it is a declaration change too, but it widens the
helper list for every subsystem.

**`current_time` is exact on pipefs.** `timestamp_truncate`
(`fs/inode.c:2612-2631`): `s_time_gran = 1` (`fs/libfs.c:657`, set by
`pseudo_fs_fill_super` after `alloc_super`'s default of `1000000000`,
`fs/super.c:374`), `s_time_min/max = TIME64_MIN/MAX` (`fs/super.c:375-376`),
so the clamp (`__clamp`, `include/linux/minmax.h:181-182`: `>= hi`, then
`<= lo`) and the granularity arms change nothing. The mirror still mirrors
these decisions (constant outcomes, Appendix A).

**Where the records are consumed, in C order:**

| Operation | Reads | Path |
|---|---|---|
| `pipe2` | 1 | `get_pipe_inode:909` → `simple_inode_init_ts` (`libfs.c:2103`) → `inode_set_ctime_current:2662` → `current_time`. Then `inode_set_atime_to_ts`, `inode_set_mtime_to_ts` (`libfs.c:2105-2106`): all three stamps equal. Also on the `-ENOPKG` arm, before the free. |
| `read`, `ret > 0`, `!O_NOATIME` | 1 or 2 | `touch_atime:2111` → `atime_needs_update:2094` (read 1) → `relatime_need_update:1944` is `true` at once (`MNT_RELATIME` is not set: `kern_mount` gives `pipe_mnt` only `MNT_INTERNAL`, `fs/namespace.c:1219-1220`) → `timespec64_equal(&atime, &now)` (`:2100`). If equal: no update, no second read. Else `inode_update_time:2054` (`i_op->update_time` is NULL: `empty_iops`, `fs/inode.c:170`) → `generic_update_time:2036` → `inode_update_timestamps:2007` (read 2) → `!timespec64_equal(&now, &atime)` (`:2013`) → `inode_set_atime_to_ts`. |
| `write`, `ret > 0` | 1 or 2 | `file_update_time:2271` → `inode_needs_update_time:2217` (read 1) → `IS_NOCMTIME` (`:2221`, `i_flags`) → `!equal(mtime, now)` (`:2225`), `!equal(ctime, now)` (`:2229`). If both equal: `ret <= 0` (`:2272`) returns. Else `__file_update_time:2244` → `inode_update_time` → `inode_update_timestamps:1997` → `inode_set_ctime_current` (read 2, **sets ctime**) → `!equal(now, ctime_old)` (`:1998`), `!equal(now, mtime)` (`:2000`, sets mtime). |

With `HZ=250` the coarse clock moves in 4 ms steps, so consecutive
operations land both inside and across a tick: both outcomes of every
`timespec64_equal` arise without steering. (The second read is never equal
to a stamp the first read found different: `stamp < now1 ≤ now2`; the mirror
still decides it from the record, and A3 checks the operands.)

**A3 at header lines.** `timespec64_equal` (`include/linux/time64.h:46-50`)
is `(a->tv_sec == b->tv_sec) && (a->tv_nsec == b->tv_nsec)`: two
short-circuit comparisons on line 49, declared as two **repeatable**
comparison decisions `timespec64_equal.sec` / `.nsec` (`eq`, non-constant,
empty spans: they share a line), anchored in `time64.h`, which joins
`kcov.json`'s files. Each caller's `if` is its own non-comparison decision
with spans in `fs/inode.c` (the pattern of `__refcount_sub_and_test` and
`kref_put`). The check accepts header sites whose containing function is
listed (`evaluator/coverage.py:56-62`, `attributable`), so
`inode_needs_update_time`, `inode_update_timestamps` and
`atime_needs_update` must be in `kcov.json`'s functions. Matching is
existential per line per operation (`correspondence/README.md`), so the
three `equal` calls of one write are distinguished only by their operands;
that is the known A3 weakness, not a new one. **Verify first** (section
10): that GCC emits two `cmp` records at `time64.h:49` rather than one
xor-or test.

**Decoding.** `hiddenTimespec s : M Timespec64` reads 16 bytes and splits
them into two signed 64-bit words. The domain filter's placeholder for a
16-byte clock must be a sane `timespec64` (`tv_nsec < 10^9`):
`Defs.hidden` gains a `len == 16` clock case, `(1700000000 + n, 0)`. [AGENT]

**Timestamps are not observed directly in stage 1** (no `fstat`). The
evidence that the clock flows into state is A3 on the `equal` operands:
a mirror whose stored `mtime` is wrong reports a different left operand on
the next write (section 8, P-M4). `fstat` is the stage-2 way to observe
them (section 9).

**Sites consumed on a side path.** `O_NOTIFICATION_PIPE` consumes the
creation read and then frees the inode (`fs/pipe.c:929-935`): the record is
consumed exactly there. `O_NOATIME` on the read end (via `F_SETFL`)
suppresses `touch_atime` (`fs.h:2578`): no record, and a mirror that reads
anyway fails with "a record was not consumed"/"no record left" — a
record-count check that costs nothing (P-M12, P-M17).

## 4. The two mirror collapses to open, without breaking eventfd

1. **`put_file_access`'s read-only arm** (`fs/internal.h:116-117`;
   `i_readcount_dec`, `include/linux/fs.h:3125-3129`, real because
   `CONFIG_FILE_LOCKING=y`). Today `unsupported "i_readcount_dec"`
   (`Leanux/FS/FileTable.lean`, `putFileAccess`). The read end of a pipe is
   `FMODE_READ` only, so every close of a last read-end reference reaches
   it. Open it as `inodeReadcountDec : Option InodeId → M Unit` with arms
   `.pipefs id` (decrement; `BUG_ON(< 0)` is `invariant`), `.anon`
   (`unsupported`, unreachable: the slice has no read-only anonymous
   files), `.fixture` (`unsupported`), `none` (`invariant`). The matching
   increment at `file_init_path` (`fs/file_table.c:349-350`), today a
   recorded branch with a cut, becomes `inodeReadcountInc` with the same
   arms. Eventfd files are `O_RDWR`, so their path is unchanged.
2. **`vfs_write`'s `write_iter` arm** (`fs/read_write.c:682-683`). Today
   `unsupported "new_sync_write"`. Open it as `newSyncWrite fid buf count
   pos` mirroring `fs/read_write.c:580-595`: `init_sync_kiocb` (`ki_flags =
   f_iocb_flags`), `ki_pos = ppos ? *ppos : 0`, `iov_iter_ubuf`,
   `f_op->write_iter` through `fopWriteIter`, `BUG_ON(-EIOCBQUEUED)`
   (`unsupported`, as `newSyncRead`), and `if (ret > 0 && ppos)` (`:592`,
   two operand decisions sharing a line; `ppos` is NULL for `FMODE_STREAM`
   files, so the store never happens). `fopWriteIter` has arms
   `.pipefifo → pipeWrite`, `.eventfd → invariant` (`eventfd_fops` has
   `write`, not `write_iter`: `fopsOf` never routes it here), `.fixture →
   unsupported`. Eventfd keeps `fopWrite`.

Three more arms gain a `.pipefs` case without changing eventfd's: `inodeIsReg`
(false: `S_IFIFO`, so `file_start_write`/`file_end_write` return at once,
`fs.h` via `Leanux/FS/ReadWrite.lean`), `inodeIsChr` (false), `inodeFlags`
(`0`) and `inodeFileType` (`S_IFIFO`) in `Leanux/FS/Fcntl.lean` (the
`setfl.not_fifo` decision becomes false for pipes, which is exactly why
`O_DIRECT` is accepted). `Fops` gains `pipefifoFops := { readIter, writeIter,
release, fasync, poll, unlockedIoctl, open, spliceWrite }` with `llseek =
false` (`fs/pipe.c:1232-1241`: no `llseek`, so no `FMODE_LSEEK`;
`check_flags` NULL; `fasync` set, so `F_SETFL FASYNC` stays `unsupported`).

**`Syscall.write` carries bytes.** Today `write (fd count) (word : UInt64)`;
it becomes `write (fd count : Nat) (buf : ByteArray)` and `eventfdWrite` takes
`buf`'s first 8 bytes as `ucnt` (`copy_from_user(&ucnt, buf, sizeof(ucnt))`,
`fs/eventfd.c`). `World.userOut` becomes `Option ByteArray`;
`eventfdRead` writes its 8 bytes. The runner computes both (section 6).

**Repeatable decisions.** `pipe2` runs `alloc_empty_file`, `file_init_path`,
`alloc_file` and `fd_install` twice in one operation, and the `-EMFILE`
unwind runs two `fput`s whose `__fput`s run in the same operation's task
work. The check rejects a non-repeatable decision reported twice, so the
interface commit flips to `repeatable`: `fdInstallBacking`,
`fdInstallResizeInProgress`, `fdInstallSlotBusy`, `allocEmptyFile*`,
`iocbFlags*`, `fileInitPath*`, `allocFileOk`, `allocFilePseudoErr`,
`fputLast`, `fputNotOpened`, `fputInInterrupt`, `fputKthread`,
`fputTaskWorkAddFailed`, `fputFinal*`, `eventpollReleaseLinked`,
`fileOwnerRelease`, `putFileAccess*`, `fileFree*`. This loosens the
"reported once" check for eventfd operations on those decisions; accepted
and noted. [AGENT]

## 6. Harness and trace contract

**`pipe2` producer with two descriptors.** Trace v1 gains the operation
`{"op": "pipe2", "flags": u32}`. A descriptor argument may now be
`{"pipe": i, "end": 0}` (read end, `fd[0]`) or `{"pipe": i, "end": 1}`
(write end, `fd[1]`) naming an earlier `pipe2`; `{"ref": i}` must still
name an `eventfd2`/`dup`/`dup3`, and a `ref` to a `pipe2` is invalid. A
failed `pipe2` resolves its ends to `-1`, as failed producers do today
(`harness/guest.c:245-255`, `Leanux/Runner.lean` `resolveFD`). Wire:
opcode 14 (appended to `OPCODES`), descriptor kinds 2 and 3 with the
producer index as value; the guest keeps the pair in `struct observation`.
Observation: `pipe2` gains `"fds": [r, w]`, or `null` on failure.

**Large I/O buffers with a pattern both sides compute.** `count` for `read`
and `write` is bounded by `MAX_IO = 69632` (17 pages: one write can overfill
the default 16-slot ring and get the partial count `65536`, `fs/pipe.c:559`;
reads can drain it). The write buffer is determined by the trace: bytes 0-7
are the `value` field little-endian (as today, so eventfd writes are
unchanged), and byte `k ≥ 8` of operation `i` is
`P(i, k) = (7·i + 13·k + 17·(k >> 8)) mod 256` (a 256-byte or page
misalignment changes it). The guest fills a static buffer; the runner builds
the same `ByteArray`. Nothing new crosses the wire. [AGENT]

**Read observation (USER decision Q1; recommendation [AGENT]).** Linux
returns up to 64 KiB per read and the comparison child repeats it, so
full hex (139 KB per large read, twice) would press the 16 MiB batch limit
(`harness/linux.py:31`) in a corpus with a few dozen large reads.
Recommended format for every `read` observation:
- `"bytes"`: hex of the **first 64 bytes** returned (all of them when
  `ret ≤ 64`; today's eventfd observations are unchanged);
- `"digest"`: hex of **BLAKE2s-256 over all `ret` bytes** when `ret > 0`,
  else `null`.

BLAKE2s is recommended over SHA-256 because the mirror already has a tested
`blake2s` (`Leanux/WG/Blake2s.lean:68`, with `#guard` vectors) and Python
has `hashlib.blake2s`; only the guest needs a new C implementation (~120
lines, the RFC 7693 reference, self-tested at startup against the same
vectors, fail-noisy). SHA-256 would need one implementation in C and one in
Lean. Alternatives: (b) full hex up to 4096 bytes plus the digest beyond;
(c) full hex always, raising the batch limit. The digest is what detects a
wrong slot boundary, offset or ordering anywhere in a 64 KiB read; the head
makes small mismatches readable.

**SIGPIPE: block it, observe it (recommended [AGENT]; USER decision Q2).**
Today the guest installs no disposition, so the first `-EPIPE` would kill
the trace child (`SIGPIPE`'s default action). The guest will:
- `sigprocmask(SIG_BLOCK, {SIGPIPE})` in the trace child before
  `KCOV_ENABLE`, and fail the trace if `sigpending()` is nonzero at that
  point;
- after each `write`, call `sigpending()` (outside the coverage window,
  which ends at the captured count) and report `"sigpipe": 0|1`; any other
  pending signal fails the trace (environment failure).

Why blocking, not `SIG_IGN`: with the signal blocked the kernel takes the
full generation path — `send_sig(SIGPIPE, current, 0)` (`fs/pipe.c:458`) →
`send_sig_info` (`kernel/signal.c:1656-1666`, `SEND_SIG_NOINFO`) →
`do_send_sig_info` (`:1297-1309`) → `send_signal_locked` (`:1214-1252`,
`force = false`: the pid is nonzero) → `__send_signal_locked`
(`:1073-1188`): `prepare_signal` (`:902-967`) returns true because
`sig_ignored` (`:104-123`) sees the signal in `t->blocked` (`:111`);
`legacy_queue` (`:1068-1071`) short-circuits a second `-EPIPE` while the
first is still pending; `__sigqueue_alloc` (`:404-442`, `override_rlimit`
because `SEND_SIG_NOINFO` is special, `:1113-1114`); `sigaddset` (`:1168`);
`complete_signal` (`:994-1066`) returns at `:1006-1011` because
`wants_signal` (`:977-992`) is false for a blocked signal and the type is
`PIDTYPE_PID`. No `signal_wake_up`, so `TIF_SIGPENDING` stays clear and
`signal_pending(current)` (`fs/pipe.c:563`, only on the blocking path
anyway) is unaffected. With `SIG_IGN`, `prepare_signal` returns false at
`sig_handler_ignored` (`:75-80`) and nothing is observable; with the
default, the child dies. The pending set persists for the rest of the trace
(every later `write` reports `1`), which makes `legacy_queue`'s true arm
reachable; each of the two children per trace starts with an empty set
(`fork` clears it). Nothing in a trace unblocks or drains it.

**The signal path in the mirror [AGENT, see Q3].** `Leanux/Kernel/Signal.lean`
mirrors the chain above down to the pending set, with its decisions
(Appendix A: ~16) and the functions `send_sig`, `send_sig_info`,
`do_send_sig_info`, `send_signal_locked`, `__send_signal_locked`,
`prepare_signal`, `complete_signal`, `__sigqueue_alloc` listed in
`kcov.json` (`kernel/signal.c` joins the anchored files; `sig_ignored`,
`sig_task_ignored`, `legacy_queue`, `wants_signal` are inlines reached
through them). `inc_rlimit_get_ucounts` (`kernel/ucount.c`) and
`signalfd_notify` (`include/linux/signalfd.h:19-23`, no waiters) are cuts.
The alternative is a cut at `fs/pipe.c:458` with the contract "SIGPIPE
joins `pending`; nothing else, because it is blocked" — ~16 decisions and
one file fewer, at the cost of leaving a subsystem on the modeled path
unmirrored. The signal path has no hidden inputs either way.

**errno allowlists** (`evaluator/protocol.py` `SEMANTIC_ERRNOS`):
`pipe2 {22 EINVAL, 24 EMFILE, 65 ENOPKG}`; `write` adds `32 EPIPE`; `fcntl`
adds `16 EBUSY` (`EINVAL`, `EPERM`, `EBADF` are already listed); `read`
unchanged (`EAGAIN` is listed). `ENFILE` and `ENOMEM` stay environment
failures.

**fcntl commands.** `F_GETPIPE_SZ` (1032) and `F_SETPIPE_SZ` (1031)
(`F_LINUX_SPECIFIC_BASE = 1024`, `include/uapi/asm-generic/fcntl.h:192`,
`include/uapi/linux/fcntl.h:34-35`) join `FCNTL` in `harness/trace.py`,
`FcntlCmd` in the mirror and the runner's parser. `arg` stays `u32`
(`do_fcntl` passes `argi = (int)arg`, `fs/fcntl.c:447,540`; `pipe_fcntl`
takes `unsigned int`).

**A hang guard [AGENT].** A mispredicted "does not block" hangs the guest
(recon risk). The trace child arms `alarm(5)` before each operation and
`alarm(0)` after it, both outside the coverage window; `SIGALRM`'s default
action kills the child, the parent logs `LEANUX_CHILD_FAILURE`, and the batch
continues. The domain filter (`leanux-model --domain`) still runs first and
excludes traces the mirror knows would block, as for eventfd.

**Comparison child.** `LEANUX_CMP_RESULT` gains `fds`, `digest` and
`sigpipe` so the determinism check (`harness/linux.py:385-390`) covers them.

**Evaluator protocol** (`evaluator/protocol.py`, `harness/linux.py`
`_check_observation`): the new fields per operation kind, `MAX_IO` as the
byte-count bound, the `digest` regex (64 hex), `fds` shape, `sigpipe ∈
{0,1}`. `evaluator/check.py`'s `guest_timeout` gets a per-byte allowance for
large operations (TCG copies 64 KiB in well under a millisecond; the
allowance is for safety).

## 10. Risks

- **Medium: a mispredicted block hangs the guest.** Mitigated by the domain
  filter and the `alarm` guard (section 6); a hang costs one child, not the
  batch.
- **Medium: A3 at `time64.h:49`.** If GCC compiles `timespec64_equal` to a
  single xor-or test, the two declared comparisons find no record. Verify
  on the first trace's `LEANUX_CMP` records before declaring; the fallback
  is non-comparison decisions for the `equal` tests (A3 then checks nothing
  about the clock flow, and P-M4 must be rejected another way — by `fstat`
  in stage 2). Same for `clamp` at `fs/inode.c:2617` (branch-free `cmov`
  is fine: the records exist, the witnesses do not).
- **Medium: `pipe_bufs` baseline** (section 5): one probe run settles it.
- **Low: truthiness tests declared as comparisons.** `if (!buf->len)`,
  `if (ret)`, `!pipe->readers` etc. are declared `eq`/`ne` 0 with a
  constant; if a site has no `cmp` record (`test` without a callback), the
  check says so ("no comparison recorded at condition") and the decision is
  demoted. The existing `eventfd_read.empty` is the precedent that it works.
- **Low: `current_time`'s consumer frame.** It is a non-static exported
  function (`fs/inode.c:2644`) calling the hooked reader and then
  `timestamp_truncate`, so not a tail jump; if inlined into a caller the
  inline frame still names `inode.c:2648`. Confirmed by the first records.
- **Low: `s_flags` and `last_ino` are not derived**, so their decisions are
  non-comparison (declared, not asserted). Stage 2 may derive `s_flags`
  from `sget_fc`/`vfs_get_tree` and promote them.
- **Low: `repeatable` flips** weaken the once-only check for eventfd on the
  listed decisions.
- **Low: observation volume** with the digest format is bounded (≤ 128
  hex + 64 hex per read).
- **Noted: `pipe_release`'s `!readers != !writers`** (`:734`) is declared
  non-comparison: the compiler may emit two zero-tests and an xor; its
  outcome is still checked by A2.

  to 4096 plus digest, or full hex always?
- **Q2 (SIGPIPE):** block in the trace child and observe with `sigpending`
  per write (recommended), or `SIG_IGN` (nothing observable, shorter C
  path)?
- **Q3 (signal generation):** mirror `kernel/signal.c` down to the pending
  set (recommended, ~16 decisions, one more anchored file), or cut
  `send_sig` with a contract?
- **Q4 (`user->pipe_bufs`):** track from a runner baseline of 0 and declare
  the comparison (recommended), or exclude from A3 like `nr_files`?
- **Q5 (`MAX_IO = 69632`):** 17 pages so one write overfills the default
  ring; a smaller cap (16384) would still reach every arm via `F_SETPIPE_SZ`
  but not the 64 KiB partial write.
