## 1. Target

**W1.** Every arm of `drivers/net/wireguard/netlink.c` that a natural netlink
message reaches and that the mirror today pins to a constant or to
`unsupported`, becomes a computed decision with a trace that reaches each
outcome: device lookup by ifindex, `-EBADR`, `-EOPNOTSUPP` for a non-WireGuard
device, `WGPEER_A_PROTOCOL_VERSION`, a peer without a public key, an allowed
IP missing an attribute, a malformed nested entry (the one rejection that is
the parse's own, not a policy length), unknown flag bits, endpoint attributes
of the wrong length or family, nonzero `sin6_flowinfo` and `sin6_scope_id`,
IPv4-mapped IPv6 endpoints. Observables: the operation's error code, the next
dump (data), and the decision stream (A2).

**W2.** The dump becomes the kernel's: a sequence of skbs of a known size,
each filled by one `wg_get_device_dump` call that stops at the first
attribute that does not fit, with the `next_peer` / `next_allowedip` cursors,
the `allowedips_seq` check, the dead-cursor exit, the `NLM_F_DUMP_INTR` flag,
and `NLMSG_DONE` placement. The guest steps a dump one `recvmsg` at a time so
a `wg_set` can run between two dump calls. Observables: the per-message
attribute structure and flags of every message (new), the coalesced device
state as today, and the decision stream, which now includes the
`-EMSGSIZE` outcomes.

Both stay inside the AGENTS.md altitude: no bytes, no C memory; attribute
*sizes* are modeled because they decide control flow (`nla_put` fails on
`skb_tailroom`), attribute *bytes* are not.

### 2.2 Generic netlink parsing: strict everywhere; which errors

- `wg_genl_family` sets no `.validate` flags (netlink.c:610-634), so the
  top-level attributes are parsed with `NL_VALIDATE_STRICT` for both the
  doit (genetlink.c:1093-1095 with `GENL_DONT_VALIDATE_STRICT` unset) and the
  dump (`genl_start`, :976-982, `GENL_DONT_VALIDATE_DUMP[_STRICT]` unset).
- `nla_parse_nested` (include/net/netlink.h:1310-1322) first rejects an entry
  without `NLA_F_NESTED` with `-EINVAL` ("NLA_F_NESTED is missing", :1315-1318),
  then parses strictly. This is the one rejection that is the parse's own
  check, not a policy-table length: **W1 uses it as the single sanctioned
  malformation** to reach the `ret < 0` arms at netlink.c:461 and :590.
- Under `NL_VALIDATE_STRICT` the policy tables produce (lib/nlattr.c):
  `-EINVAL` for an unknown type (`type == 0 || type > maxtype`, :604-631), a
  fixed-width integer of the wrong length (:413-419), a nested-policy
  attribute without `NLA_F_NESTED` or a non-nested one with it (:423-436),
  trailing bytes (:646-651), a `NUL_STRING` without NUL or longer than
  `IFNAMSIZ - 1` (:471-496); `-ERANGE` for a `NLA_BINARY` outside its declared
  range (`nla_validate_range_unsigned`, :170-237, "integer out of range"):
  keys of a length other than 32 (`EXACT_LEN`), an endpoint shorter than 16,
  an allowed-IP address shorter than 4 (`MIN_LEN`). **All of these are P8**
  and stay out (section 5).
- A `GET_DEVICE` without `NLM_F_DUMP`, or a `SET_DEVICE` with it, is
  `-EOPNOTSUPP` from `genl_get_cmd` (genetlink.c:1179-1183) before any
  WireGuard code runs; also out.

### 2.3 The dump's skb budget (net/netlink/af_netlink.c)

- `__netlink_dump_start` runs `start` (:2427-2434; `wg_get_device_start`
  via `genl_start`), sets `dump_done_errno = INT_MAX` and **calls
  `netlink_dump` once inside the `sendmsg`** (:2437-2440), then returns
  `-EINTR` (:2450), which `netlink_rcv_skb` turns into "no ack" (:2551). A
  `start` error returns before that and is acknowledged as `NLMSG_ERROR`
  (:2556), with the request echoed (`NETLINK_F_CAP_ACK` unset, :2478).
- Each `netlink_dump` allocates a fresh skb of `alloc_size =
  max(min_dump_alloc, NLMSG_GOODSIZE)`; if the socket's `max_recvmsg_len` is
  larger, it first *attempts* that size with `__GFP_NORETRY` and no direct
  reclaim (:2279-2290) and falls back on failure. The skb is trimmed to
  exactly `alloc_size` of tailroom (:2312). Generic netlink passes no
  `min_dump_alloc` (genetlink.c:1059-1066).
- `max_recvmsg_len` is the running maximum of the lengths passed to
  `recvmsg` on that socket, capped at `SKB_WITH_OVERHEAD(32768)` (:1940-1943).
- `NLMSG_GOODSIZE = SKB_WITH_OVERHEAD(PAGE_SIZE) = 4096 -
  SKB_DATA_ALIGN(sizeof(struct skb_shared_info))` (include/linux/netlink.h:270-273,
  include/linux/skbuff.h:255-257). `sizeof(struct skb_shared_info)` is
  **0x140 = 320** in the reference build (`llvm-dwarfdump-19
  --name=skb_shared_info .artifacts/kernel-net-choice/vmlinux`:
  `DW_AT_byte_size (0x0140)`; `CONFIG_MAX_SKB_FRAGS=17`), `SMP_CACHE_BYTES`
  = 64 (`X86_L1_CACHE_SHIFT=6`), so **`NLMSG_GOODSIZE = 3776`** and
  `SKB_WITH_OVERHEAD(32768) = 32448`.
- **Today the budget is not deterministic.** The guest reads every netlink
  reply with a 65536-byte buffer (`nl_buffer`, guest.c:218, :251 on `main`),
  so `max_recvmsg_len` is 32448 from the family lookup on, and every dump
  skb is 32448 bytes if an order-3 no-reclaim allocation succeeds and 3776 if
  it does not. The current `DUMP_BOUND` 3000 (`Netlink.lean`) is below both,
  which is why nothing has shown. W2 removes the ambiguity (section 4.1).
- After the callback: `-EMSGSIZE` with data in the skb means "more"
  (:2333-2334); a positive return keeps the dump running; the skb is queued
  without `NLMSG_DONE` if the callback wants more **or fewer than
  `nlmsg_total_size(4) = 20` bytes remain** (:2339-2346); otherwise `NLMSG_DONE`
  carrying `dump_done_errno` is appended to the same skb (:2350,
  `netlink_dump_done` :2225-2250), `done` runs (:2369, `wg_get_device_done`)
  and `cb_running` clears (:2372).
- `recvmsg` dequeues one skb, then, if the dump is still running and the
  receive queue is below half `sk_rcvbuf`, runs the next `netlink_dump`
  (:1974-1980). With `MSG_DONTWAIT` and nothing queued it returns `-EAGAIN`
  before that block. **So dump call k+1 runs inside the `recvmsg` that
  returns chunk k**, and dump call 1 runs inside the `sendmsg`.
- A second dump request on a socket whose dump is running gets `-EBUSY`
  (:2406-2407) as an `NLMSG_ERROR` queued behind the pending chunk.
- Closing the socket with a dump running calls `done` synchronously
  (:768-773). The trace child exits before the parent deletes `wg0`
  (guest.c:985), so a trace may end mid-dump without leaking the device
  reference `wg_get_device_start` took.

### 2.4 The consistency flag and the cursors

- `cb->seq = wg->device_update_gen` at every dump call (netlink.c:222);
  `genl_dump_check_consistent` (:229 → include/net/netlink.h:1193-1199) sets
  `NLM_F_DUMP_INTR` on a data message iff `prev_seq` is set and differs,
  i.e. iff `device_update_gen` changed between two dump calls. It changes only
  at netlink.c:523, reached by every `wg_set_device` that passes the lookup,
  flag and permission checks (device.c:323 initializes it to 1). The
  `NLMSG_DONE` header is checked too (af_netlink.c:2237) but can never carry
  the flag: the last callback set `seq` and `prev_seq` equal.
- `get_peer` on a cursor peer (`ctx->next_allowedip` set) skips the fixed
  part (:123-163) and resumes the allowed-IP list from the node (:175-176).
  `ctx->allowedips_seq` is taken at the first visit (:166-167) and compared
  at every later one (:168-169); a mismatch ends the peer **without** an
  allowed-IPs nest. `wg_allowedips_insert_v4/v6`, `remove_by_peer` and
  `free` bump `seq` (allowedips.c:262, :287, :298, :311); the mirror already
  keeps it (`AllowedIps.seq`, bumped at `AllowedIps.lean:179, :188, :260`
  and in `removeByPeer`).
- `next_peer_cursor` advances only past peers whose `get_peer` *completed*
  (:270-276); the peer that did not fit is retried in the next chunk from
  its cursor state. On the first chunk the cursor is NULL, so a first peer
  that does not fit leaves `ctx->next_peer` NULL and **the next chunk
  repeats the whole device part** (:231-252) before continuing the peer.
- A cursor peer removed between calls (`is_dead`, peer.c:89) cancels the
  peers nest and ends the dump (:264-268); the dump's reference is released
  at :282 (the last one, so the kref release path runs in that operation).
- `get_peer`'s `err:` path (:194-196) cancels the whole peer nest but does
  **not** reset `ctx->allowedips_seq` if it was already taken at :167
  (the `allowedips_nest` start failing at :171-173 is the case). The retry
  in the next chunk then sees `seq_changed` if any allowed-IP change
  happened in between, and dumps the peer without IPs.

### 2.5 Attribute sizes the kernel computes

`nla_put` fails iff `skb_tailroom(skb) < nla_total_size(len) =
NLA_ALIGN(4 + len)` (lib/nlattr.c:969); a nest start is a zero-length put
(include/net/netlink.h:1925-1950); `nla_nest_cancel` restores the tail
(:1975); `nlmsg_put` needs `nlmsg_total_size(payload)` (:955-958).
`CONFIG_HAVE_EFFICIENT_UNALIGNED_ACCESS=y`, so `nla_put_u64_64bit` adds no
pad attribute (include/net/netlink.h:2028-2074).

| Put (in C order) | Bytes |
|---|---|
| `genlmsg_put`: nlmsghdr 16 + genlmsghdr 4 | 20 |
| `WGDEVICE_A_LISTEN_PORT` u16, `FWMARK` u32, `IFINDEX` u32 | 8 each |
| `WGDEVICE_A_IFNAME` (`strlen + 1`; "wg0" → 4) | `NLA_ALIGN(4 + len + 1)` = 8 |
| `WGDEVICE_A_PRIVATE_KEY`, `PUBLIC_KEY` (if `has_identity`) | 36 each |
| `WGDEVICE_A_PEERS` nest | 4 |
| peer nest; `WGPEER_A_PUBLIC_KEY` | 4; 36 |
| first visit only: `PRESHARED_KEY`; `LAST_HANDSHAKE_TIME` (16); `KEEPALIVE` u16; `TX_BYTES`, `RX_BYTES` u64; `PROTOCOL_VERSION` u32 | 36; 20; 8; 12, 12; 8 |
| `WGPEER_A_ENDPOINT`: none / `sockaddr_in` 16 / `sockaddr_in6` 28 | 0 / 20 / 32 |
| `WGPEER_A_ALLOWEDIPS` nest | 4 |
| per allowed IP: nest; `CIDR_MASK` u8; `FAMILY` u16; `IPADDR` 4 or 16 | 4; 8; 8; 8 or 20 → 28 (v4) / 40 (v6) |
| `NLMSG_DONE` (4-byte errno) | 20 |

The device part is 56 bytes without identity, 128 with; a peer's fixed part
136/156/168 by endpoint. These are exactly the numbers the current
`dumpSize` uses (it was right); W2 only applies them per put instead of to a
bound.

## 3. W1 — netlink completeness

### 3.1 Trace schema (harness/trace.py, harness/wg.py; the mirror's Runner mirrors it)

All additions are optional keys; every existing trace means what it did.

- **Device selector**, on `wg_set`, `wg_get` and the W2 dump ops:
  `"device": {"ifname": s}` (1-15 characters, `NUL`-terminated by the
  encoder) | `{"ifindex": n}` (u32) | both | `{}`; absent means
  `{"ifname": "wg0"}`. The encoder emits `WGDEVICE_A_IFNAME` and/or
  `WGDEVICE_A_IFINDEX` accordingly, in that order.
- **Device flags**: `config.flags` (u32, raw `WGDEVICE_A_FLAGS`); exclusive
  with `replace_peers`, which stays as sugar for 1.
- **Peer**: `public_key` becomes optional (absent → no attribute);
  `flags` (u32, raw; exclusive with the three booleans);
  `protocol_version` (u32); `malformed: "not_nested"` (the entry is encoded
  as today but without `NLA_F_NESTED`).
- **Endpoint**: as today plus `flowinfo` (u32, IPv6 only, bytes as given),
  `scope_id` (u32, IPv6 only), `af` (u16, overrides the `sa_family` bytes),
  `len` (16..128, the attribute length: the canonical 16/28-byte `sockaddr`
  is zero-padded or truncated). `addr` of family 6 may be any 16 bytes,
  including `::ffff:a.b.c.d`. `sin_zero` is always zero (section 5).
- **Allowed IP**: any subset of `family`, `addr`, `cidr` (absent → no
  attribute); `af` (u16, overrides the family value); `addr` of 4..20 bytes
  (even hex digits) regardless of family; `malformed: "not_nested"`.

The validator rejects what the policy would (P8): keys other than 32 bytes,
`len` < 16, `addr` < 4 bytes, `ifname` > 15 — fail-closed, with the reason.

### 3.2 Mirror (Leanux/WG/Netlink.lean set path, Leanux/Env.lean, Leanux/Runner.lean)

- `DeviceAttrs.device : DeviceRef` (`ifname? × ifindex?`). `lookupInterface`
  becomes: `lookupBothOrNeither` computed; `lookupHasIfindex` computed;
  resolution against the **environment's device table**
  (`Env.netDevices : List {name, ifindex, linkKind : Option String}` =
  `lo` 1 none, `sit0` 2 `"sit"`, plus `wg0` at its current ifindex with
  `"wireguard"` when `Kernel.wg` is some — L's cursor gives 3 at creation
  and 4 after a delete/re-create); `lookupNoDev`, `lookupNoLinkOps`,
  `lookupKindMismatch` computed from the row; `lookupNoKind` stays
  `false` with the structural reason in its comment. The table is fixture
  knowledge and lives in `Env.lean`, not in `WG/`.
- `PeerEntry := malformed | attrs PeerAttrs`; `AllowedIpEntry` likewise.
  `setDevParseErr` / `peerAipParseErr` are computed (`entry matches
  .malformed`) and return `-EINVAL`, documented as the cut-point contract
  of `nla_parse_nested` (include/net/netlink.h:1315-1318).
- `PeerAttrs.publicKey : Option Key` (`peerHasPubkey` computed;
  `peerPubkeyLen` stays `true` as P8); `protocolVersion : Option Nat`
  (`peerHasProtocol`, `peerBadProtocol` computed); `flags` raw.
- `AllowedIpAttrs` fields become `Option` (`aipNoFamily/NoAddr/NoCidr`
  computed); `family` and `addrLen` already drive the rest.
- `EndpointAttr` gains `flowinfo`, `scope`; `Endpoint` gains
  `flowinfo : Nat := 0` (data: stored and dumped, never compared;
  `wg_socket_endpoint_from_skb` zeroes it). `scope` already exists and is
  already compared in `endpointEq` (`eqScope6`); the netlink path now sets
  it. The dump emits both for IPv6 endpoints.
- `getPeerDump`'s JSON endpoint gains `flowinfo` and `scope_id` (IPv6); the
  harness decoder (`_decode_endpoint`) stops discarding bytes 4-8 and 24-28
  and **rejects** a nonzero `sin_zero` (fail-noisy; the encoder never sends
  one).
- Data plane hand-off: an IPv6 endpoint with nonzero `scope_id` or a
  v4-mapped address changes `send6`'s route lookup; that is W9. Until W9,
  `Env.deliver` must treat such endpoints as `unsupported` when a datagram
  is actually sent to them (today non-loopback destinations already are;
  the rule must also catch `::ffff:127.0.0.1` and a scoped `::1`).

## 4. W2 — multi-message dumps

### 4.1 Make the budget deterministic: one recv length

Fixture change, no kernel change: **every `recv` on the generic-netlink
sockets uses a buffer of exactly `NL_RECV_LEN = NLMSG_GOODSIZE = 3776`
bytes** (guest.c: `nl_receive`, `resolve_wireguard_family`, and the new
stepped recv). Then `max_recvmsg_len ≤ NLMSG_GOODSIZE`, the
`alloc_min_size < max_recvmsg_len` attempt at af_netlink.c:2282 never
happens, every dump skb is `alloc_skb(3776, GFP_KERNEL)` — a single page,
with reclaim, whose failure is `-ENOBUFS` and an environment failure, not
a silent fallback — and **every chunk has exactly 3776 bytes of room**. A
chunk always fits the receive buffer, and the guest checks `MSG_TRUNC`
anyway (fail-noisy). The family lookup's reply is a few hundred bytes.

Rejected alternatives: keeping 65536 (nondeterministic, section 2.3);
a per-trace `recv_len` (adds a hidden monotone per-socket state for no new
path: the same chunk sizes are reachable with 3776 and ≤ 256 IPs).

Consequence for existing traces: none in behavior (all current dumps are
under 3000 bytes), but every network trace's genl socket now reads this
way, so the whole WireGuard suite is the regression check for this step.

The constant is pinned twice: by the DWARF size (2.3) and by the first
boundary-targeting traces (4.8), whose `expect` labels fail loudly if the
room were anything else.

### 4.2 The stepped dump: two ops and a dump socket

- **`DUMP_FD = 8`**: a second `NETLINK_GENERIC` socket, opened (after the
  one at 7, no `SOCK_CLOEXEC`) only for traces that contain a stepped op.
  The guest sees this from the parsed ops; the fixture record for such
  traces becomes `reserved [0..8]`, `free [9, rlimit-1]` (the check at
  harness/linux.py:390 learns the two shapes; `rlimit_nofile ≥ 9` for such
  traces); `Runner.initialKernel` gets fd 8 as a foreign
  `"generic-netlink-dump"` file and `nextFd 9` for them. Why a second
  socket: a `wg_set` ack queued behind a pending dump chunk on one socket
  would be received after the chunk, and that `recv` would run the next
  dump call (2.3), entangling the two ops. Why a fixture fd rather than a
  temporary socket inside the op: `socket()`/`close()` inside the coverage
  window would put `alloc_fd`/`fd_install`/`close_fd` decisions into the op,
  which the mirror would then have to model for socket files.
- **`wg_get_start`** `{"op", "device"?}`: `sendmsg(DUMP_FD, GET_DEVICE,
  NLM_F_REQUEST|NLM_F_DUMP)`. ret 0 always (a start error is an `NLMSG_ERROR`
  queued for the next recv; `-EBUSY` likewise). Inside this op's window the
  kernel runs `wg_get_device_start` and dump call 1.
- **`wg_get_recv`** `{"op"}`: one `recvmsg(DUMP_FD, 3776, MSG_DONTWAIT)`.
  ret 0, or `-EAGAIN` (errno 11, semantic) when nothing is queued. Inside
  this op's window the kernel runs the *next* dump call (if the dump is
  still running), including `wg_get_device_done` when it finishes.
- **Interleaving rule** (from 2.3): a `wg_set` placed between `wg_get_start`
  and the first `wg_get_recv` runs between dump calls 1 and 2; one placed
  between recv k-1 and recv k runs between dump calls k and k+1. `wg_set`
  stays on fd 7. Any other op may be interleaved too.
- **Observation** of `wg_get_recv` (ret 0): `"messages"`, the list of
  netlink messages that one recv returned, in order:
  `{"kind": "data", "flags": 2 | 18, "attrs": {...}}`,
  `{"kind": "done", "flags": 2, "error": e}`, `{"kind": "error", "error": e}`.
  `attrs` holds exactly the attributes present, in the kernel's names:
  `listen_port`, `fwmark`, `ifindex`, `ifname`, `private_key`, `public_key`
  when the device part is present; `peers` (a list) iff the `WGDEVICE_A_PEERS`
  nest is present (it is cancelled on the dead-cursor and empty-list exits);
  each peer exactly its attributes (`public_key`, and on a first visit
  `preshared_key`, `last_handshake`, `keepalive`, `tx_bytes`, `rx_bytes`,
  `protocol_version`, `endpoint` if any), with `allowed_ips` present iff the
  nest is present — possibly `[]`, which is what the kernel emits when the
  first IP does not fit (netlink.c:182). Absent and empty are different
  observations. The guest's `LEANUX_WG` record carries per message its
  kind, `nlmsg_flags` and payload; the harness decodes (`decode_messages`),
  never coalesces, and rejects anything the kernel cannot produce.

### 4.3 Mirror: the dump machine and the put model

- **`Leanux/Kernel/NetlinkDump.lean`** (new): the per-socket state the C
  keeps in `netlink_sock` and `netlink_callback`, as a cut-point contract
  for af_netlink.c's dump loop, with no `Decision` constructors (its
  outcomes are observed by A1 through the messages; af_netlink.c stays
  unanchored, see 4.9):
  `NlSock { queue : List Skb, cbRunning : Bool, dumpDoneErrno : Int,
  prevSeq : Nat, ctx : DumpCtx }`, two instances (fd 7 and fd 8).
  `Skb { room : Nat, len : Nat, messages : List Message }` with
  `room = 3776` fresh.
  `netlinkDumpStart` (start callback; on error queue `.error e`; else
  `cbRunning := true, dumpDoneErrno := INT_MAX`, then `netlinkDump`);
  `netlinkDump` (fresh skb; if `dumpDoneErrno > 0` call the dump callback
  and apply the `-EMSGSIZE`-with-data rule; queue without DONE if the
  callback wants more or `room < 20`; else append DONE, run `done`, clear
  `cbRunning`); `netlinkRecvmsg` (pop one skb or `-EAGAIN`; then
  `netlinkDump` if running). The second start while running is
  `unsupported` (4.9).
- **`DumpCtx { wg, nextPeer : Option PeerId, allowedipsSeq : Nat,
  nextAllowedip : Option NodeId }`**, the C's `struct dump_ctx`, kept in the
  socket. The cursor peer's reference is taken at netlink.c:281 and
  released at :282 / :310 through the existing `peerGet`/`peerPut`, so the
  kref release of a cursor peer removed in between runs in the right op.
  `nextAllowedip` is consulted only after the `seq` check (the node may be
  gone from `Device.nodes`).
- **Put model**: `Skb.put (n : Nat) : M Bool` returns `room < n` (the
  failure) and otherwise reserves; `nestStart` is `put 4` and records the
  saved room; `nestCancel` restores it. `wgGetDeviceDump` and `getPeerDump` /
  `getAllowedips` keep their decisions but compute each `*Put*Failed`,
  `*NoNest`, `getPeerAipFail`, `dumpGetPeerFail`, `dumpFirst`,
  `getPeerFirst`, `getPeerSeqUnset/Changed`, `dumpCursorSet/Dead`,
  `dumpOutNotDone/HasCursor`, `dumpDone` from the state, in the C's order
  and with the C's cancels (section 2.4 and 2.5 are the specification).
  `wgGetDevice` is split into `wgGetDeviceStart`, `wgGetDeviceDump` (one
  call = one chunk, returning `skb.len` / 0 / `-EMSGSIZE` as the C), and
  `wgGetDeviceDone`. `dumpSize` and `DUMP_BOUND` go.
- **`requireNotPending`** applies per dump call, as today, for every peer
  the call dumps: a stepped dump over a running device with a handshake
  worker pending stays `unsupported`, fail-noisy.
- **`Decision.lean`**: the dump-call decisions (`dumpNoHdr` … `dumpDone`,
  `getDoneHasWg`) become `repeatable`: in `wg_get` (op 9) several dump
  calls run in one op. The `get_peer` decisions already are.
- **The `NLM_F_DUMP_INTR` flag**: computed in `wgGetDeviceDump` from
  `prevSeq` and `deviceUpdateGen` (the C of include/net/netlink.h:1196-1198);
  data, not a decision (header line, unanchored).

### 4.4 Reaching each path (what the generator must build)

| Path | How | What Linux emits |
|---|---|---|
| a peer split across chunks | enough peers/IPs that an IP does not fit | chunk k ends with the peer's IPs that fit; chunk k+1 starts with `{public_key, allowed_ips: [...]}` |
| each `get_allowedips` put failing | room before the IP: 0 → nest; 4, 8 → cidr; 12, 16 → family; 20, 24 (v4) / 20..36 (v6) → addr | same shape; the decision differs (A2 false spans: 85, 86, 92-93) |
| each first-visit put failing | room before the peer in [40, 72] → psk (the nest and key fit, 36 more do not); +36 → last handshake; +20 → keepalive; … (2.5) | the peer is absent from chunk k (nest cancelled) and complete in chunk k+1 |
| `allowedips_nest` start failing | room exactly the fixed part | as above, plus the retry carries `allowedips_seq` (2.4): with a `wg_set` touching allowed IPs in between, the peer is dumped **without IPs** |
| device part repeated | first peer > 3648 bytes: ≥ 87 IPv6 or ≥ 125 IPv4 allowed IPs (with identity and an IPv6 endpoint) | chunk 2 begins with `listen_port … public_key` again |
| `seq_changed` | split a peer, then a `wg_set` that inserts/removes any allowed IP or `replace_allowed_ips` on a peer with IPs | the continued peer is `{public_key}` only; the dump goes on |
| dead cursor | complete peer P in chunk k, then `wg_set` with `remove`, `replace_peers`, or a private key whose public key is P's | chunk k+1 is a data message with `attrs: {}` (no device part, no `peers`), then `done`; P's kref release runs in that op |
| `NLM_F_DUMP_INTR` | any `wg_set` reaching netlink.c:523 between dump calls, even an empty one | flags 18 on the next data message only |
| DONE in a separate skb | room after the last peer < 20 | the data message alone, `done` in the next recv |
| start error | `device: {"ifname": "sit0"}` on `wg_get_start` | first recv: `{"kind": "error", "error": -95}` |
| `-EAGAIN` | one recv too many | ret -11 |

### 4.5 `wg_get` (op 9) after W2

Unchanged interface: the guest's `nl_receive` loop drains to `NLMSG_DONE`
(now in 3776-byte chunks), the harness coalesces to the canonical `device`
state, the mirror runs the same dump machine to completion in the op and
coalesces with the same rule (`coalesce : List Message → Json`, one
function, used only here). The coalescing rule gains the repeated device
part (identical values required; fail-noisy otherwise) and keeps the
continued-peer rule. A2 sees every chunk boundary of op 9 (the
`-EMSGSIZE` decisions, repeatable); the stepped ops see flags and
placement. Keeping `device` keeps the 1,288-trace corpus and the stage
reports' expectations meaningful.

### 4.6 Harness decoder (harness/wg.py)

`decode_messages(records)` for the stepped ops (4.2), `decode_dump` on top
of it for op 9; `_decode_peer` no longer defaults `allowed_ips`; the
endpoint decoder as in 3.2. Unit tests in `harness/test_wg.py` cover a
continued peer, an empty `allowed_ips` nest, a repeated device part, a
cancelled peers nest, and a DONE in its own message.

### 4.7 Lifting the 32-IP cap

`allowed_ips` per peer: 256 (validator, Runner, guest). The guest's
`MAX_PAYLOAD` (32768) and `line[4 * MAX_PAYLOAD]` stay; the validator
bounds the encoded `WG_CMD_SET_DEVICE` payload at `MAX_PAYLOAD - 64` and
rejects larger configurations with the size in the message (16 × 256 IPv6
would be ~180 KB). 256 reaches every path in 4.4 (the repeated device part
needs 87 IPv6 allowed IPs on the first peer; a peer spanning into a third
chunk needs 177: 86 fit in chunk 1 after the device part, 90 in chunk 2
after the repeated device part, key and nests).

### 4.8 Generators (scripts/wg-n2-corpus.py; scripts/wg-n1-corpus.py for W1)

- A **boundary-targeting** generator builds configurations whose dump
  reaches a chosen room before a chosen put, using the size table of 2.5
  in Python (the same table the mirror uses; a wrong table makes a trace
  miss its target, not pass falsely). Each such trace states what it is
  for with `expect` labels (`get_allowedips.put_family_failed=1`, …).
- **`expect` on unsteered traces**: today `expect` requires `steer`
  (harness/trace.py:84-90). W2 lifts that (one validator line; the check
  already enforces `expect` on any agreeing trace). This pays: every
  targeted trace becomes self-verifying, and a wrong `NLMSG_GOODSIZE` fails
  at the first such trace instead of silently moving every boundary.
- Random traces (`evaluator/generate.py`'s WireGuard classes) gain stepped
  dumps with interleaved sets at low frequency; W1's selectors and
  malformations at low frequency, so the existing streams keep their
  content (the generator's seeding convention).

### 4.9 What W2 does not model, and why

- af_netlink.c is not anchored and `netlink_dump` has no decisions: its
  outcomes (DONE placement, more/done, the `-EMSGSIZE` conversion) are all
  visible in the stepped messages (A1); anchoring would add a listed
  function with the "function reached" obligation for no mutant that A1
  does not already reject. Revisit if a defect shows otherwise.
- A second `wg_get_start` while the socket's dump runs: `unsupported` (the
  `-EBUSY` arm is af_netlink.c's, three lines if a generator ever wants it;
  the domain filter drops such traces rather than failing).
- `sk_rcvbuf`: at most one skb is queued at any time (each recv pops one
  and pushes at most one), so the half-`rcvbuf` condition at
  af_netlink.c:1975 is always true; stated, not modeled.

### 4.10 Mutants (`N2-…`)

| Mutant | Rejected by |
|---|---|
| N2-M1 IPv6 `IPADDR` counted as 16 bytes (should be 20) | A1 messages (boundaries shift); A2 `getPeerAipFail` outcome index |
| N2-M2 `seq` mismatch ignored (IPs continue) | A1 messages; A2 `getPeerSeqChanged` (span 169 covered, reported 0) |
| N2-M3 dead cursor continues with the next peer | A1 messages (peers listed; `peers` present) |
| N2-M4 cursor advanced past the peer that failed | A1 messages (a peer missing) |
| N2-M5 device part not repeated when the first peer spans | A1 messages |
| N2-M6 DONE never appended to the data skb | A1 messages (`done` one recv later) |
| N2-M7 `NLM_F_DUMP_INTR` never set | A1 flags |
| N2-M8 room 4096 | A1 messages; A2 boundary decisions; the `expect` labels |
| N2-M9 failed IP nest not cancelled (room not restored) | A1 DONE placement on a boundary trace |
| N2-M10 first-visit put failure keeps the partial peer | A1 messages |
| N2-M11 op 9 coalescing drops a continued peer's IPs | A1 `device` |

N2-M3, M5, M6, M7 are rejected **only** by the per-message observation:
that is the evidence the new instrument pays for itself. N2-M1 and M8 are
also caught by A2, but only once multi-chunk dumps exist, which needs 4.1.

## 5. Out of scope, with reasons

| What | Why |
|---|---|
| Policy-table rejections (2.2): key lengths, `len` < 16, `addr` < 4, integer widths, unknown or `UNSPEC` types, trailing bytes, `NLA_F_NESTED` on `WGPEER_A_ALLOWEDIPS` / `WGDEVICE_A_PEERS`, `ifname` > 15 | P8: no WireGuard code runs; the validator rejects them fail-closed |
| `GET_DEVICE` without `NLM_F_DUMP`, `SET_DEVICE` with it, wrong family/version header | genetlink's, before the driver (genetlink.c:1172-1183) |
| `-EPERM` (`!net`, `!ns_capable`) | needs a user namespace (`CONFIG_USER_NS` unset) or netns exit: W8 |
| `lookup_interface`'s `!kind` | structurally dead (every registered `rtnl_link_ops` has a kind) |
| `sin_zero` bytes of an IPv4 endpoint | copied and dumped by the C, but no natural client sets them; the decoder requires zero (fail-noisy) rather than carrying 8 bytes of padding through the state |
| `send4`/`send6` with a scoped or v4-mapped endpoint | routing decisions: W9; `unsupported` until then (3.2) |
| `-EBUSY`, `sk_rcvbuf` | 4.9 |
| A dump that fails to allocate its skb (`-ENOBUFS`) | a single-page `GFP_KERNEL` allocation; an environment failure if it ever happens |
| The 32448-byte skb path (`__GFP_NORETRY`) | made unreachable by 4.1 on purpose |
| `genl_op_lock`, `rtnl_lock`, `device_update_lock` | lock regions are atomic steps on one CPU, as everywhere in the mirror |

## 6. Risks

1. **`NLMSG_GOODSIZE`.** Pinned by DWARF (320) and by `expect`-labelled
   boundary traces; a wrong value fails loudly at the first of them.
2. **The recv-length change touches every network trace.** The full
   WireGuard suite plus the integrated branches' corpora are the
   regression; nothing should move (all dumps < 3000 bytes).
3. **fd 8 for stepped traces** changes the FS mirror's initial state only
   for those traces; `test_evaluation` gets a case for each fixture shape.
   If the user prefers no new fixture fd, the alternative is a socket opened
   inside the op, which costs modeling `socket()` and `close()` on socket
   files (section 4.2) — a larger change.
4. **Workers during a stepped dump.** `requireNotPending` guards tx_bytes
   and endpoints; traces mixing `wg_inject` with stepped dumps are allowed
   only when the mirror can prove nothing is pending at each dump call.
5. **Repeatable dump decisions** in op 9: both outcomes of `dumpFirst`,
   `dumpPeerListEmpty`, … may appear in one op; the check's "both" rule
   covers repeatable decisions, but the first witnessed order is now per
   call — the order check compares first witnesses only, so this is sound.
6. **Generator cost.** 256-IP configurations make large sets (11 KB) and
   long mirror runs (trie inserts); keep them to the targeted traces.
7. **Merge load.** `Netlink.lean`, `Runner.lean`, `trace.py`, `protocol.py`
   are edited by both streams in different regions (section 7 fixes the
   split first).
