# Oracle kernel for the choice stream (docs/2026-10-03-choice-stream-strategy.md):
# step 1 and step 2 (steering) user-approved 2026-10-03; the D1 sprint's
# dispatch sections (stream A) and resched records (integration) and the D3
# sprint's timer sections, arm record and virtual time advance
# (docs/2026-10-05-d3-timers.md, stream K) awaiting the user's approval;
# A streams K1 (the allocation hook) and K2 (steering a forced failure)
# (docs/2026-10-05-a-alloc.md, sections 4-5) and A2's task-instance
# steering (section 19) awaiting the user's approval with A.
# kernel/config-x86_64-net (unchanged) with kernel/patches/choice-stream.patch
# (sha256 4274afa340f5fe7f9178eca8ab56d2e0b8278fa63e734d8e9adda2ba53a4edf0)
# applied alone to the locked source, built with LEANUX_KERNEL_PROFILE=net-choice.
# The patch (kernel/patches/gen-choice-stream.py) records random draws and
# clock reads at generic interception points (drivers/char/random.c,
# kernel/time/timekeeping.c), lets a trace steer named call sites through a
# per-handle schedule loaded by ioctl (kernel/kcov.c), and opens dispatch
# sections in process_one_work (kernel/workqueue.c), the NET_RX vector
# (kernel/softirq.c) and call_timer_fn (kernel/time/timer.c) for the armed
# dispatch set, with start and stop records and a dropped-section counter
# (kernel/kcov.c, include/linux/kcov.h, include/linux/sched.h), and writes a
# resched record when __cond_resched schedules inside a task section
# (kernel/sched/core.c). D3: mod_timer writes an arm record (kind 303,
# {jiffies, expires}) for an armed timer function when the dispatch set was
# loaded with KCOV_DISPATCH_ARM_RECORDS; KCOV_LEANUX_TIME_ADVANCE advances
# jiffies_64 (leanux_time_advance, kernel/time/timekeeping.c, refused unless
# the timekeeper is refined-jiffies) and records kind 304 {before, after},
# with interrupts disabled from the jump until the record (D3 integration).
# A (K1): slab_alloc_node (mm/slub.c) and __alloc_pages_noprof
# (mm/page_alloc.c) call kcov_alloc_pre/post with the entry's explicit return
# address; armed by KCOV_LEANUX_ALLOC_LOAD (ioctl 205: ranges and the
# inventory flag; n = 0, flags = 0 is disarmed, the default), they write
# kind 305 (outcome, gfp, size or order, up to four unwound return
# addresses) in recording contexts; KCOV_LEANUX_ALLOC_STATUS (206) counts
# records and unwinds. Unarmed: one load per allocation, no records. No
# A (K2, section 5): a kind-305 steering entry (the per-handle schedule,
# KCOV_LEANUX_STEER_LOAD) forces the allocation to fail. Chain containment
# decides both the naming test and the head match, so helper sites (the
# consumer's frame above the allocation) are steerable; the forced record
# is written from the pre side with outcome 0 and the steered bit, and the
# allocator returns NULL. A __GFP_NOFAIL allocation is never forced (its
# entry stays). The steer entry's former pad word is now `flags`
# (KCOV_STEER_CHAIN, bit 0; kind 305 only). The companion control kernel
# kernel/patches/choice-stream-alloc-controls.patch (profile net-choice-actl,
# never an oracle) adds load flags for controls K1/K4/K5; the oracle's load
# rejects them.
# A2 (section 19): kcov_steer_find also returns the schedule of the task's
# own KCOV instance (loaded there by a trace with no remote instance, an FS
# trace, before KCOV_ENABLE), consulted in the task's own context; a
# network trace's task instance carries none, so its remote lookup is
# unchanged. Two lines in kernel/kcov.c.
# D3+A integration (task/int-da): one combined patch, D3 as on task/d3-int
# and A as on task/a2, and the dispatch set's capacity KCOV_DISPATCH_MAX
# raised from 16 to 32 (record-only infrastructure; harness/guest.c
# DISPATCH_MAX and harness/trace.py's wire bound match it). Nothing else.
